# Traps

Эти различия не закодированы в именах команд; ошибка может выглядеть как успех.

- Читайте доступность харнесса из `surface`, `version_source` и `diagnostic`,
  не из строки `version`.
- `state: available` с пустым `installations` значит «поддерживается, но не
  установлен». Не называйте это установленным.
- Принятый локальный паспорт — происхождение и согласие владельца, не
  готовность к публикации и не platform-verified.
- `ready: true` у проверки паспорта — локальная структурная полнота одной
  ревизии, не разрешение на облачную запись.
- Подпись выпуска провайдера не доказывает совместимость. Нужны и доверие к
  выпуску, и conformance.
- Байты даёт только каталожная команда, предназначенная для offline closure.
  Ключ объекта не даёт права скачивать.
- `candidate_id` — не идентификатор Component. Идентификатор Component
  появляется только после `component adopt`.
- Называйте GitHub origin точным только при `provenance.kind: github` и
  `state: exact`. Имя каталога кэша — не доказательство.
- `harness_id: null` агент не назначает харнессу.
- В browser device flow покажите verification URL и user code; не завершайте
  grant за пользователя.
- Не конструируйте web-маршруты. Canonical links и `cli_argv` даёт `link web`.
- `source: cache` — прошлое: покажите `checked_at` и не выдавайте это за
  текущее облачное состояние.
