# Decisions

Задача пользователя — граница полномочий. Локальные обратимые шаги внутри этой
задачи идут без нового вопроса (`ADR-0150`).

`mutability` и `confirmation` независимы. `confirmation: none` — не согласие.
`plan_digest` — машинная привязка точных байт, не человек.

- `read` — наблюдение.
- `plan` — точный предмет последующего apply.
- `apply` — когда текущий запрос уже это разрешает.
- `destructive` — только когда нет пути восстановления.

Отдельное решение пользователя нужно, когда: меняется видимость или доступ
существующего объекта; привязывается **чужой** аккаунт или новые сторонние
учётные данные; повышаются системные привилегии; данные, target или backup
удаляются без восстановления.

Нерешённый инженерный выбор, непроверенный или experimental объект, Git
promotion и выкатка проверенной работы в этот список не входят. Unverified
остаётся помеченным unverified. Experimental может войти в композицию по
полномочию задачи и от этого не становится `authoritative`.

Для `explicit_flag` на оставшихся остановках получите решение, затем передайте
параметр, который назвал дескриптор. Для `plan_digest` выполните названную
plan-команду и передайте digest, который вернул CLI. Не считайте его сами.
Устаревший план перепланируется автоматически.

Проверки digest, предусловий и идемпотентности — механические, не вопросы.
Неопределённость запускает дополнительный осмотр или обратимый эксперимент.
