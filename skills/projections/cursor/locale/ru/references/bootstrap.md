# Bootstrap

Если `ai-stp` не найден, используйте установку из PyPI:
`uv tool install ai-stp-cli`. Если отсутствует uv, используйте официальные
инструкции <https://docs.astral.sh/uv/getting-started/installation/>.
Обновите поиск команд в shell и проверьте, что выбранный ai-stp принадлежит этой
установке. Checkout репозитория или бинарь провайдера не заменяют CLI.

Выполните `ai-stp task intents --json` и стартуйте подходящий shipped intent.
Используйте `ai-stp doctor` только когда пользователь спросил, что сломано.
`ai-stp version` объясняет работающий билд, если вопрос именно в этом.
Не набирайте `ai-stp capabilities`. В ответе каждый command path.
Идентичность установки — intent `inspect`.

Используйте уже названные пользователем корни проектов, не спрашивайте повторно.
Для «этого проекта» осмотрите текущий workspace и определите настоящий корень.
Спрашивайте о каталоге только при отсутствии контекста или неоднозначном выборе.
По умолчанию не сканируйте домашний каталог.

Используйте `ai-stp project discover` и `ai-stp project index` для выбранного
проекта, когда нужны его паспорт или индекс. `ai-stp component inventory` —
экспертное discovery. Не набирайте `ai-stp component adopt` чтобы поставить
готовый сетап; каталог регистрируйте intent `author`.

Публичный каталог и получение его объектов работают без аккаунта. Вход нужен
для запрошенного приватного доступа, публикации или синхронизации.
Продолжите по [install](install.md), [compose](compose.md) либо [self](self.md),
если требуется установка самого Skill в другой харнесс.
Первая обнаружимость харнесса — intent `initialize`, а не вставка этого файла
в project instruction.
