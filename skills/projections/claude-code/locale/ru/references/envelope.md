# Envelope

Каждый machine JSON-ответ — ровно один объект.

При `ok: true` результат в `data`. `warnings` можно показать, не делая вызов
неуспешным. При `ok: false` `error.code` — стабильный код из закрытого реестра,
а `next_actions` называет разумный следующий шаг.

Найдите `error.code` в `error_codes` из machine help и следуйте `handling`,
вместе с `retryable` и `next_actions` ответа. Не выбирайте действие только по
классу кода выхода: один класс может быть конфликтом, устаревшим планом или
запросом решения пользователя.

Повторяйте только при `retryable: true`. После неподтверждённого timeout сначала
проверьте фактический эффект через предложенную status или recovery команду.

`next_actions` — упорядоченная подсказка, не разрешение. Каждый элемент —
исполняемый argv этой CLI. В нём нет многоточия вместо предыдущего вызова.
Недостающие значения — плейсхолдеры в угловых скобках, узкое чтение help по
семейству команды или типизированное продолжение с непустым `missing`.
Человеческое продолжение биндит `task answer` без недостающего значения;
этот argv не исполняйте.
`continuations[0].actor` — JSON-поле (`cli`, `human` или `external`), а не
личность пользователя. Вы — coding agent: запускайте `task intents` и
`task start` сами. Исполняйте continuation `argv` только когда это поле
`cli`. Когда поле `human`, напечатанный `argv` не исполняйте (value нарочно
отсутствует); сразу ответьте из разговора через `task answer`. Ждать
человека — не работа. `task start` уже продвинул задачу; не вставляйте
`task continue`, когда `actor` равен `human` или continuations нет.
Когда `actor` — `external`, покажите payload один раз; `argv` не исполняйте.
`provider-too-old` — не login. Device-code можно позже продолжить через
`task continue` после браузера; не опрашивайте в цикле.

`continuations` аддитивно: старые сборки поле опускают. Когда `ok` равен
false и `error.details.state` — `failed`, задача settled: пустой
`continuations` значит остановиться. Не выдумывайте `task get`. Сверьте следующий вызов
с уже полученным дескриптором установленной версии. Схему ответа читайте, когда
неясны его поля. Исправленные входы или свежий план — новая операция, а не
слепой повтор постоянной ошибки. Соблюдайте указанное сервером время повтора и
сохраняйте завершённую работу во время ожидания.
