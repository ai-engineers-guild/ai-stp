# Установка, сохранение и возврат

Для готового сетапа каталога выполните следующий путь по установленным
дескрипторам. Передавайте реальные идентификаторы и digest между шагами.

1. Определите харнесс, корень проекта и нужную область нативной установки.
   Точную версию пользователя прочитайте через `ai-stp registry version`;
   иначе найдите её через `ai-stp registry search` и `ai-stp registry show`.
   Выбранный сетап должен принадлежать этому харнессу.
2. Выполните `ai-stp registry acquire` для точной версии. Команда получает
   замкнутый граф компонентов и проверенные файлы для локальной сборки.
   Одного чтения метаданных недостаточно. Публичное получение не требует входа.
3. Если нужна программа харнесса, следуйте [provider](provider.md). Разделяйте
   prefix программы и target конфигурации. Осмотрите существующую конфигурацию
   и сохраните её, если задача предполагает замену.
4. Выполните `ai-stp install plan` для полученного сетапа, проекта, target и
   поддерживаемого scope. Другой вариант — передать только что подтверждённый
   proposal из [compose](compose.md). Это альтернативные входы.
5. Изучите пути, конфликты, нужную авторизацию и восстановление. В рамках
   полномочий задачи выполните `ai-stp install approve` с полученными operation
   и plan digest, затем `ai-stp install apply` для той же операции. Названия
   параметров берите из дескрипторов.
6. Прочитайте `ai-stp install status` и `ai-stp target status`. Проверьте точный
   сетап и target, а не только exit code. `pending_authorization` означает
   незавершённый вход, а не необходимость повторить apply.

Для обновления используйте `ai-stp setup update plan` и
`ai-stp setup update apply`. После прерывания сначала откройте
[recover](recover.md). Для отката провайдера используйте
`ai-stp target rollback` и точную ссылку на резервную копию из свидетельств
операции.

Для полного сохранения конфигурации используйте `ai-stp setup preserve plan`
и возвращённый маршрут операции. Сохранённую идентичность найдите через
`ai-stp setup preserved list` / `ai-stp setup preserved show`.
`ai-stp setup restore plan` выбирает её, сначала сохраняет текущие правки и
завершается свежей проверкой покрытого нативного состояния. Offline-запись не
является свежим измерением. `ai-stp setup import plan` используется, когда
существующая конфигурация должна стать редактируемым локальным сетапом.
