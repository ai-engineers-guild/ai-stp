# ai_stp

`ai_stp` — система для создания, проверки, хранения, подбора и установки полных конфигураций AI-харнессов.

Первичный потребитель продукта — агент пользователя, работающий через CLI. Веб по `ADR-0018` владеет учётной записью и публичным каталогом: профиль и приватность, устройства и их отзыв, собственные объекты, публикация, права, жалобы и минимальное администрирование. Создание паспортов, индексация, подбор, сборка, проверки и установка остаются за CLI и агентом; веб показывает их результаты, но не выполняет их.

## Что такое сетап

Сетап — полная конфигурация конкретного харнесса:

- системные инструкции (`AGENTS.md`, `CLAUDE.md` и аналоги);
- навыки;
- MCP-серверы и их настройки;
- хуки;
- команды;
- агенты и субагенты;
- плагины и маркетплейсы, если они поддерживаются харнессом;
- память, правила, параметры и вспомогательные инструменты как содержимое
  `instruction`, `skill` или `setting`, а не отдельные виды компонентов.

Каждая устанавливаемая версия сетапа привязана к конкретному харнессу, его версии, операционной системе, точным версиям компонентов и результатам проверок.

## MVP

Поддерживаемые харнессы:

| Статус | Харнессы |
|---|---|
| Основная поддержка | Claude Code, Codex, Grok Build |
| Бета-поддержка | Pi, OpenCode, Cursor, Antigravity |
| Ограниченный режим | `undefined` для неизвестного харнесса |

Основной путь:

```text
установка CLI
→ обнаружение окружения и харнесса
→ паспорта разработчика и устройства
→ индекс проекта
→ поиск и сборка сетапа
→ проверки
→ план установки
→ резервная копия
→ применение через провайдер харнесса
→ запуск и проверка состояния
→ восстановление при ошибке
→ необязательная синхронизация с облаком
```

## Локальный и облачный режимы

Без аккаунта доступны:

- локальный реестр;
- паспорта;
- индексация проектов;
- публичный каталог в режиме чтения;
- подбор и установка публичных объектов.

После авторизации через Google или GitHub доступны:

- облачная копия личного реестра;
- приватные сетапы и компоненты;
- публикация;
- устройства и их ключи;
- выдача доступа по идентификатору аккаунта и приглашениям на подтверждённую почту;
- жалобы на объекты каталога.

## Стадия

Единственный владелец текущего состояния фаз —
[`docs/engineering/implementation-roadmap.md`](docs/engineering/implementation-roadmap.md).
README не копирует его таблицу: механизмы CLI, platform и release evidence движутся с
разной скоростью, и единая фраза «готово» скрыла бы незакрытые внешние доказательства.

Реализованы local-first CLI, platform/worker/API, web, семь provider systems,
публикация и production pull-deploy. Roadmap отделяет работающие механизмы от
ещё не повторённого exact-current evidence. Release target — Linux, Windows и
macOS на обеих архитектурах; mock, build или старый provider tag не закрывает
real-product criterion.

`main` — единственная линия. Проверенное изменение может попадать туда прямым
commit/push текущего authenticated владельца задачи; PR используется для
независимого review или изоляции параллельного изменения, а не как обязательный
ручной approval. Порядок описан в `docs/engineering/git-workflow.md`.

## Лицензия

AGPL-3.0-or-later. Лицензия распространяется и на работу платформы по сети: если `ai_stp` предоставляется пользователям как сервис, исходный код изменённой версии остаётся доступным им.

Каталог принадлежит гильдии. NDDev предоставляет публичные провайдеры харнессов; они остаются отдельными проектами под своими лицензиями и этим репозиторием не перелицензируются.

Опубликованные пользователями компоненты и сетапы являются самостоятельными произведениями и лицензируются своими авторами; лицензия платформы на них не распространяется.
