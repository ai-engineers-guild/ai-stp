# Провайдер и программа харнесса

Провайдер управляет нативной конфигурацией, программа харнесса запускает coding
agent. Получением провайдера владеет CLI. При обычной установке не задавайте
override провайдера: CLI найдёт настроенный или управляемый экземпляр либо
получит его автоматически. Следуйте источнику, объявленному установленной
версией; новые версии CLI сами подготавливают проверку происхождения PyPI.
Для этого пути не требуйте ручной установки gh, Rust или отдельного verifier.

`ai-stp harness install` устанавливает программу в явный prefix, отдельный от
target конфигурации. Проверьте `ai-stp harness status`. Наличие программы,
работающая конфигурация и вход в аккаунт самого харнесса — разные результаты.
После установки программы продолжите установку сетапа. Самому ai-stp ключ
модели не нужен.

Для явного получения или исправления используйте `ai-stp provider fetch`,
`ai-stp provider trust`, `ai-stp provider check` и
`ai-stp provider conformance`. Сохраняйте возвращённый манифест и свидетельства;
не выбирайте бинарь перебором всех файлов каталога загрузки. Происхождение
провайдера и соответствие протоколу проверяются отдельно.

Для обновления провайдера используйте `ai-stp provider update plan` и
возвращённый маршрут применения. Программу обновляет `ai-stp harness update`;
сетап и сам CLI имеют отдельные playbook. Замена провайдера не обновляет сетапы.

`ai-stp toolchain profile` и `ai-stp toolchain install` нужны только для
реальных требований выбранной среды. Отсутствие необязательного инструмента
не требует массовой установки постороннего ПО.
