# Провайдер и программа харнесса

Провайдер управляет нативной конфигурацией, программа харнесса запускает coding
agent. Получением провайдера владеет CLI. При обычной установке не задавайте
override провайдера: CLI найдёт настроенный или управляемый экземпляр либо
получит его автоматически. Следуйте источнику, объявленному установленной
версией; новые версии CLI сами подготавливают проверку происхождения PyPI.
Для этого пути не требуйте ручной установки gh, Rust или отдельного verifier.

Исполняемым файлом harness и его обновлениями управляют пользователь и вендор.
ai-stp определяет установленную версию через `ai-stp toolchain harnesses` и
получает компоненты установки конфигурации, а не дистрибутивы harness.
Интент `install` настраивает сетап. Наличие программы, рабочая конфигурация и
вход у вендора — отдельные результаты. Для ai-stp ключ модели не требуется.

Не набирайте `ai-stp provider fetch`. Для явного получения или исправления
берите из machine help `ai-stp provider trust`, `ai-stp provider check` и
`ai-stp provider conformance`. Сохраняйте возвращённый манифест и свидетельства;
не выбирайте бинарь перебором всех файлов каталога загрузки. Происхождение
провайдера и соответствие протоколу проверяются отдельно.

Для обновления провайдера не набирайте `ai-stp provider update plan`.
Семейство — в machine help. Сетап и
сам CLI имеют отдельные playbook. Замена провайдера не обновляет сетапы.

Не набирайте `ai-stp toolchain profile` или `ai-stp toolchain install` для
обычного сетапа. Отсутствие необязательного инструмента не требует массовой
установки постороннего ПО.
