# Быстрый старт

Короткий путь, который реально готовит машину: поставить CLI, увидеть чего не
хватает, создать локальные идентичности, затем прочитать публичный каталог.
Выбор и применение сетапа — следующая глава, не эта.

Исполняемый файл — `ai-stp`. Дистрибутив на PyPI — `ai-stp-cli`. Команда
`uv tool install ai-stp` ставит пакет, который этот проект не публикует.

## Установить CLI

```bash
uv tool install ai-stp-cli
ai-stp version --json
```

Если оболочка не находит `ai-stp`, каталог инструментов `uv` не в `PATH`.
См. [Диагностику](troubleshooting/index.md).

## Спросить установку, что она умеет

```bash
ai-stp doctor --json
ai-stp capabilities --json
```

`doctor` — чтение. Он не создаёт устройство, паспорт и проект. Он сообщает о
CLI, локальном реестре, устройстве, toolchain, Agent Skill и о тех harness,
которые на машине уже есть.

`capabilities` отвечает уже: с какими поверхностями этот билд умеет говорить
прямо сейчас. Поддержку harness нельзя выводить из строки версии.

## Создать локальные идентичности

Для локальной работы аккаунт не нужен. Нужны устройство и паспорт разработчика:

```bash
ai-stp device init --json
ai-stp device show --json
ai-stp passport developer init --json
ai-stp passport device refresh --json
```

`device init` идемпотентен: второй запуск возвращает идентичность, которую
создал первый. Приватный ключ лежит в секретном хранилище ОС; если его нет, CLI
прямо говорит, что ушёл в файловый ярус.

`device reset` — другая команда. Она разрушительная, требует `--confirm` и не
является способом повторить `doctor`.

## Следовать тому, что сказал doctor

Читайте отчёт `doctor` до того, как придумывать следующий шаг.

=== "Нет toolchain"
    Инструменты первого запуска — закреплённый профиль, не случайный
    `pip install`:

    ```bash
    ai-stp toolchain profile --json
    ai-stp toolchain install --tool <id> --json
    ```

    `<id>` — инструмент, который пинит профиль. Точные имена — из
    `ai-stp help --agent --json`. `toolchain install` пишет в управляемый
    каталог и ничего не запускает из только что положенного инструмента.

=== "Нет Agent Skill"
    Это Agent Skill самого CLI, не компонент kind `skill` в сетапе:

    ```bash
    ai-stp skill status --json
    ai-stp skill install --target <dir> --json
    ```

    `--target` — каталог, из которого harness читает свой native skill.

    Когда файл на месте, агент всё равно начинает сессию с `doctor` и
    `help --agent`. См. [Agent Skill CLI](cli/skill.md).

=== "Нет программы harness"
    Установить сетап — не то же самое, что установить программу harness.
    Сама программа — `harness install`. Provider, который потом пишет нативное
    состояние, — отдельный бинарник. См. [Программу harness](cli/harness.md)
    и [Provider](cli/provider.md).

## Прочитать machine help

```bash
ai-stp help --agent --json
```

Этот конверт — реестр команд *этой* установки. Документация называет команды,
чтобы человек ориентировался; агент не должен собирать флаги из памяти, если
CLI уже отдаёт их сам.

## Посмотреть публичный каталог

Анонимное чтение не требует входа:

```bash
ai-stp registry search --json
ai-stp registry show <stable_id> --json
```

Результат — кандидат, не разрешение ставить. Перед выбором проверьте harness,
точную версию `X.Y`, линию доверия и две независимые оси verification. Как
читать карточку: [Каталог](catalog/index.md). Те же объекты на сайте:
[Веб-каталог](web/catalog.md).

Если сети нет, CLI может ответить из кэша и скажет, когда платформа в последний
раз подтвердила байты.

## Чего этот быстрый старт не делает

Он не входит в аккаунт, не собирает сетап и не пишет target harness. Это
отдельные пути с digest:

| Войти и синхронизироваться | [Вход](cli/auth.md) |

## Типичные отказы

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| `ai-stp` не найден | инструмента нет или его нет в `PATH` | поставить заново `uv tool install ai-stp-cli`, затем `uv tool list` |
| doctor говорит, что нет device | идентичность ещё не создавали | `ai-stp device init --json` |
| search отвечает из cache | платформу не достали | смотреть `checked_at`; не выдавать это за живой каталог |
| capabilities не содержат harness | этот билд не ведёт такую цель | остаться на primary harness или читать [Харнессы](harnesses.md) |

!!! note "Команды здесь — карта, не парсер"
    Если `help --agent` расходится с флагом на этой странице, прав CLI.
