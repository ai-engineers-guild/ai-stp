# Доверие и безопасность

`ai_stp` показывает происхождение, подтверждения и ограничения, но не обещает,
что любой опубликованный объект безопасен.

Что означает процент сканирования карточки —
[Проверки безопасности](../security-checks.md). Как открыть закрытый случай —
[Жалобы](../cli/report.md).

## Две оси verified

Есть две независимые оси:

- `author_verified` — платформа подтвердила автора или пространство имён;
- `component_verified` — платформа подтвердила конкретную версию объекта.

Одно не следует из другого. Подтверждённый автор может опубликовать ошибочную
версию, а неподтверждённый автор может владеть локальным объектом, который вы
точно закрепили сами.

## Линии доверия

`authoritative` — основной путь для объектов, которые можно предлагать без
экспериментального согласия.

`experimental` — объект можно рассмотреть только после явного согласия
пользователя.

`local_owner_or_pinned` — собственные, импортированные или точно закреплённые
объекты пользователя. Они выбираются напрямую после локальных проверок, но не
становятся платформенно подтверждёнными.

| Линия | Можно показывать | Можно авто-устанавливать | Требуется от пользователя |
| --- | --- | --- | --- |
| `authoritative` | да | только после обычного плана и подтверждения | проверить смысл и diff |
| `experimental` | да, с пометкой | нет без явного согласия | принять экспериментальный риск |
| `local_owner_or_pinned` | да | только как локально закреплённый объект | понимать, что это не platform-verified |

??? warning "Verified не снимает ответственность"

    Verified-статус помогает не спутать автора или объект, но не заменяет
    проверку содержимого. Особенно внимательно смотрите `mcp`, `hook` и
    `plugin`, потому что они могут расширять права или менять target.

## Согласие: allow, revoke, list

Нет ключа конфигурации со смыслом «включать все непроверенные объекты
навсегда». Согласие — это либо маркер запроса на одну команду, либо
долговременная запись на одного publisher, одну мажорную линию объекта
или авторизованный профиль задачи `full-auto`.

```bash
ai-stp consent allow --scope publisher --target <publisher_id> --json
ai-stp consent allow --scope object_major --target <stable_id>@<major> --json
ai-stp consent allow --scope task --target full-auto --json
ai-stp consent list --json
ai-stp consent revoke --scope publisher --target <publisher_id> --json
```

`--scope` — `publisher`, `object_major` или `task`. `task` — именованный
профиль, а не wildcard. У цели `publisher` или `object_major` уже должны
быть зарегистрированные объекты: пустой fingerprint — не согласие, а
отсутствие наблюдения. `task` / `full-auto` не требует совпадающего объекта.

Согласие допускает кандидатов в линию `experimental`. Оно не переводит объект
в `authoritative`, не создаёт platform verification и не отменяет проверки
установки.

Запись `publisher` или `object_major` перестаёт покрывать версию, если этой
версии нужны новые права, процессы, сеть, учётные данные или нативные
поверхности по сравнению с fingerprint на момент согласия. Активный `task`
это расширение всё ещё покрывает. Отзыв действует сразу для последующих
запросов. Отозванная более узкая запись исключает цель даже при активном
`task`.

Поиск может показать experimental-линию на одну команду без записи согласия:

```bash
ai-stp registry search --kind component --query scanner --include-experimental --json
```

Этот флаг не сохраняется. Для установки непроверенного объекта по-прежнему
нужно долговременное согласие.

Подробности: [Согласие](../cli/consent.md).

## Жалобы

Проблемный публичный объект — закрытый случай модерации, а не ветка
комментариев.

```bash
ai-stp report preview --kind component --id <id> --version 1.0 --content-digest sha256:... --json
ai-stp report confirm --plan-id <id> --plan-digest <digest> --confirm --json
ai-stp report list --json
```

[Жалобы](../cli/report.md).

## Что не делает ai_stp

`ai_stp` не вызывает интерфейсы моделей, не требует ключа модели и не разрешает
агенту обходить механические ограничения. Итоговое состояние харнесса пишет
только public provider.

Единственный исходящий запрос, который CLI делает от своего имени, — анонимный
пинг установки, и он выключен, пока вы явно не согласились. Что в него входит и
как его выключить — в [Телеметрии установки](../cli/telemetry.md).
