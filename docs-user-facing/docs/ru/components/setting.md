# `setting`

`setting` — конфигурационная часть сетапа: параметры, режимы, feature flags,
preferences, thresholds и другие значения, которые харнесс или provider умеет
применять.

Setting не должен хранить секреты. Если значение является token, password,
private key или credential, оно передаётся через поддерживаемое хранилище
секретов, а не через паспорт компонента.

## Что можно хранить

| Можно | Нельзя |
| --- | --- |
| режим выполнения | API token |
| язык интерфейса | password |
| policy flag | private key |
| лимит или threshold | `.env` содержимое |
| путь внутри target, если он не секретный | OAuth refresh token |

## Зачем setting как отдельный вид

Без отдельного вида параметры часто расползаются по инструкциям, hooks и
commands. Тогда человек не понимает, что реально поменяло поведение. Setting
делает конфигурацию видимой и сравнимой.

??? example "Пример"
    “Включить строгий режим проверки перед установкой” лучше оформить как
    `setting`, если это значение читает provider или CLI. Инструкцию “агент
    должен объяснять пользователю план” лучше оставить в `instruction`.

## Как `ai_stp` применяет setting

1. Паспорт описывает имя, тип, допустимые значения и совместимость.
2. Сборщик проверяет конфликты с другими компонентами сетапа.
3. Provider показывает diff конфигурации.
4. После подтверждения setting записывается в нативную поверхность харнесса.

!!! warning "Главная ошибка"
    Не используйте setting как удобное место для всего подряд. Если значение
    запускает действие — вероятно, это `command` или `hook`. Если оно объясняет
    процесс — вероятно, это `instruction` или `skill`.
