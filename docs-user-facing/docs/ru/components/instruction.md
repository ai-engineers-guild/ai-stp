# `instruction`

`instruction` — текстовая часть сетапа: правила поведения агента, проектная
память, стиль работы, границы полномочий и подсказки для конкретного харнесса.

Instruction не запускает код и не подключает внешний tool. Его сила в том, что
он меняет контекст, в котором агент принимает решения.

## Когда использовать

| Ситуация | Подходит ли `instruction` | Почему |
| --- | --- | --- |
| “Всегда пиши коммиты на английском” | да | это правило поведения |
| “Перед backend-тестами читай testing guide” | да | это маршрутизация внимания |
| “Запусти scanner перед push” | частично | правило можно описать, но запуск лучше оформить как `command` или `hook` |
| “Подключи GitHub MCP” | нет | это отдельный `mcp` |
| “Храни API token” | нет | секреты не попадают в компонент |

## Как это работает в `ai_stp`

1. Автор публикует или импортирует instruction с паспортом.
2. Паспорт фиксирует источник, версию, поддерживаемые харнессы и область
   действия.
3. Сборщик сетапа проверяет совместимость instruction с выбранным харнессом.
4. Provider проецирует текст в нативную поверхность: например, в файл
   инструкций, memory surface или другой поддерживаемый формат.

!!! note "Память — не отдельный вид компонента"
    Память, правила, preferences и проектные договорённости являются содержимым
    `instruction` или `setting`. Отдельного вида `memory` в `ai_stp` нет.

## Что фиксируется

| Поле смысла | Зачем |
| --- | --- |
| Происхождение | понять, кто и из какого commit/path дал текст |
| Версия | отличить неизменяемый релиз `X.Y` от следующего |
| Харнесс | не применить Claude-специфичный текст в несовместимый target |
| Scope | ограничить правило проектом, пользователем или конкретным сетапом |
| Trust line | решить, можно ли показывать или устанавливать без ручного согласия |

??? warning "Главный риск"
    Instruction может быть безобидным текстом, а может незаметно расширить
    полномочия агента. Перед установкой читайте не только название, но и diff
    содержимого.
