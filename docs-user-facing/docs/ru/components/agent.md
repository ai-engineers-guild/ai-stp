# `agent`

`agent` описывает роль специализированного агента или subagent внутри
харнесса: область ответственности, входные данные, ограничения, инструменты и
ожидаемый результат.

Agent-компонент не является отдельным сетапом. Он входит в сетап одного
харнесса и наследует его границы.

## Зачем нужны agent-компоненты

| Пример роли | Польза |
| --- | --- |
| reviewer | отделяет анализ от реализации |
| docs-writer | держит стиль и структуру документации |
| security-checker | фокусируется на рисках, а не на фиче |
| release-helper | проверяет release checklist |

## Границы роли

| Что описывать | Что не описывать |
| --- | --- |
| цель роли | глобальную замену всех инструкций |
| допустимые инструменты | секреты или персональные токены |
| критерии результата | неконтролируемый background daemon |
| когда вызывать роль | право менять внешний мир без подтверждения |

??? question "Чем agent отличается от skill"
    Skill описывает процесс выполнения класса задач. Agent описывает роль,
    которая может выполнять разные задачи внутри своей области. В реальном
    сетапе они часто работают вместе: agent использует подходящие skills.

## Как это работает в `ai_stp`

1. Паспорт agent фиксирует харнесс, роль, версию и ограничения.
2. Сборщик проверяет, поддерживает ли харнесс такую agent surface.
3. Provider создаёт нативное описание роли.
4. Статус показывает, какие роли активны в target и откуда они пришли.

!!! warning "Не расширяйте полномочия случайно"
    Agent с размытым scope быстро превращается в “делай всё”. Для MVP лучше
    иметь меньше ролей, но с ясными границами и проверяемым результатом.
