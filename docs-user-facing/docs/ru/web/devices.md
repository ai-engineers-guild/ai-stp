# Устройства

Устройства перечисляют браузеры и установки CLI, сейчас привязанные к
вашему аккаунту. Новое CLI-устройство вы одобряете, вводя код
пользователя здесь (или на `/device-login`). Отзыв устройства работает
только вперёд.

Сайт не создаёт локальную идентичность устройства. Это
`ai-stp device init`.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human | `/{locale}/devices` | после входа |
| Machine | `/{locale}/ai/devices` | та же сессия |
| Device-login | `/{locale}/device-login` | после входа, чтобы одобрить |

Нет сессии → вход. Нет CSRF cookie → выход, затем вход с
`reason=session_expired`. Онбординг pending → онбординг.

Пункт меню аккаунта **Устройства** и навигация шапки после входа оба
ведут сюда.

## Для чего этот экран

Устройства нужны, чтобы:

- видеть, какие браузеры и установки CLI могут действовать как этот
  аккаунт;
- одобрить код, который напечатал `ai-stp auth login`;
- отозвать потерянное или старое устройство.

Устройства **не**:

- запускают `device init` или `device reset`;
- показывают закрытый ключ;
- стирают локальный реестр при отзыве;
- одобряют OAuth-токен харнесса.

Отзыв останавливает **будущую облачную работу** этого устройства.
Локальные данные сохраняются. Из веба это нельзя отменить.

Пустой список: **Устройства не зарегистрированы.** Это необычно после

### Авторизовать устройство

| Поле | Подпись |
| --- | --- |
| Код устройства | Код устройства (плейсхолдер `ABCD-EFGH`) |
| Подтвердить устройство | Подтвердить устройство |

Подсказка на странице говорит выполнить команду CLI, затем подтвердить
код. Объявленная команда:

```bash
ai-stp auth login --provider github --json
```

(`google` — другой закрытый provider). В реестре нет
`ai-stp auth device`.

Query `status=ok` показывает Устройство подтверждено — вернитесь в
CLI. `status=error` просит проверить, что код ещё действует.

Отзыв текущего устройства: **Вы отозвали текущее устройство. Вы вышли
из системы.** Устаревший eTag / конфликт: обновите и решите снова.

Human / Machine: machine-Устройства перечисляют `device_id`, type,
state, last_active_at, location. Формы одобрения в них нет.

## Соответствующие команды CLI

```bash
ai-stp device init --json
ai-stp device show --json
ai-stp device reset --confirm --json
ai-stp auth login --provider github --json
ai-stp auth complete --json
ai-stp auth status --json
ai-stp auth logout --json
ai-stp passport device show --json
```

`device init` создаёт локальную идентичность (идемпотентно).
`device show` печатает, где хранится ключ. `device reset` —
**destructive** и требует `--confirm`; это не повтор `doctor`.
`auth login` / `auth complete` привязывают эту идентичность к
аккаунту. `auth status` читает отношение. `passport device show` —
голова паспорта устройства, не этот HTML-список.

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| Редирект на вход | нет сессии | войти |
| Устройства не зарегистрированы | API вернул пустоту | войти снова в этом браузере |
| Неизвестный / истёкший код | опечатка или таймаут | введите заново или запустите `auth login` снова |
| Код уже использован | resolved | запустите `auth login` снова |
| Страница устарела (CSRF) | перезагрузка | одобрите снова |
| Отзыв заблокирован (устарело / конфликт) | параллельное изменение | обновите |
| Отзыв текущего → выход | ожидаемо | войдите на оставшемся устройстве |
| CLI всё ещё работает локально после отзыва | локальные данные сохранены | ожидаемо; облачные вызовы упадут |
| Примерное местоположение Неизвестно | нет geo | не ошибка |

Не вставляйте коды устройств или ключевой материал в чат. Код —
одноразовое одобрение, не пароль для хранения.

## Браузерное устройство против CLI-устройства

| | Эта вкладка | `ai-stp` на диске |
| --- | --- | --- |
| Тип | `web` | CLI |
| Создаётся | OAuth cookie | `device init` |
| Привязывается | самим входом | `auth login` + одобрение кода |
| Закрытый ключ | session cookie | секретное хранилище ОС (или файловый fallback) |
| Отзыв на этой странице | выходит, если текущее | облачные вызовы останавливаются; файлы остаются |
| `device reset` | неприменимо | новая локальная идентичность; `--confirm` |

Одобрите код на **любом** из `/devices` или `/device-login`. CLI
опрашивает, пока `auth complete` не сможет завершиться. Повторное
одобрение потраченным кодом — `resolved`: запустите `auth login`
снова.

Machine-Устройства — список. Форма авторизации только human.
