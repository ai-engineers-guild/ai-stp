# Ваши объекты

**Объекты** — инвентарь после входа: компоненты и сетапы, которыми этот
аккаунт владеет на сервере. Паспорта, сборки и планы публикации
создаются в CLI. Сайт их перечисляет, показывает жизненный цикл и
даёт править **оформление каталога** компонента.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human list | `/{locale}/objects` | вошедшему владельцу |
| Machine list | `/{locale}/ai/objects` | та же сессия |
| Human object | `/{locale}/objects/{kind}/{stable_id}` | владельцу |
| Human version | `/{locale}/objects/{kind}/{stable_id}/versions/{version}` | владельцу |
| Human edit | `/{locale}/objects/component/{stable_id}/edit` | владельцу |
| Machine twins | `/{locale}/ai/objects/…` | та же сессия |

`{kind}` — `component` или `setup`. Иначе 404. 403/404 от API
показывается как **Этот объект недоступен вашему аккаунту.**
без намёка, существует ли объект.

**Объекты** в шапке и **Мои объекты** в меню аккаунта открывают список.

## Зачем этот экран

На **Объектах** можно:

- видеть свои имена, `stable_id`, последнюю версию, lifecycle, visibility;
- открыть публичную карточку каталога, если объект публичный;
- смотреть версии, дайджесты, evidence, eligibility установки;
- начать или продолжить план публикации, который подготовил CLI;
- править bio и медиа компонента (изменяемое оформление);
- привязать региональные сервисы (изменяемые метаданные, не дайджест).

Объекты **не**:

- создаёт компонент (это `component discover` / scaffold);
- меняет type, name, tags, source или байты версии;
- применяет сетап к harness;
- ставит `author_verified` галочкой.

Подзаголовок списка: **Собственные компоненты и сетапы. Паспорта и
сборка остаются в CLI.**

## Что на экране

### Список

Пусто: **Пока нет собственных объектов. Сначала синхронизируйте или
опубликуйте через CLI.** Два блока копирования:

```bash
ai-stp component discover
ai-stp toolchain harnesses
```

Это безопасные первые шаги (без лишних аргументов). Они не публикуют.

Строка: `object_kind`, name, `stable_id`, latest version, бейдж
lifecycle, бейдж visibility, опционально **Автор verified** /
**Компонент verified**, **Открыть публичную страницу**, **Управлять
объектом**.

### Карточка объекта

Назад к списку. Kind, name, `stable_id`. Кнопки: **Открыть публичную
страницу**; для компонентов — **Изменить био и медиа**.

**Внешние сервисы** (когда внешний каталог включён): привязать
существующие сервисы или **Создать сервис** (name, primary HTTPS URL,
коды стран). **Сохранить сервисы** — изменяемые метаданные каталога.
Дайджест версии не меняется.

**Версии**: строка — `version`, content digest, lifecycle,
**Допущен к установке** / **Установка заблокирована**. Клик ведёт на
страницу версии. Пусто: **Для объекта нет записанных версий.**

### Страница версии

| Поле | Смысл |
| --- | --- |
| Жизненный цикл | server `lifecycle_state` |
| Видимость | visibility |
| Content digest | байты этой версии или тире |
| Автор verified | независимый бит |
| Компонент verified | независимый бит |
| Допущен к установке / Установка заблокирована | eligibility сервера, не гарантия безопасности |

Таблица evidence: check, result, source, expires. Пустой evidence
допустим.

Если есть открытый план публикации, **Открыть план публикации** ведёт на
[Публикацию](publications.md). Если `can_start_publication`,
**Начать публикацию** делает POST плана (нужны CSRF и текущий
`device_id`). **Пожаловаться на версию** предзаполняет [Жалобы](reports.md).

Заметка на странице: eligibility установки и оси доверия приходят с
сервера. Это не гарантия безопасности содержимого.

### Правка оформления (только компонент)

Эти поля меняют только оформление каталога. Паспорт, type, name, tags,
source и версии остаются неизменяемыми.

| Поле | Правила |
| --- | --- |
| Описание в каталоге | Markdown оформления |
| Медиа | до пяти элементов |
| Источник элемента | загрузка, закреплённый GitHub raw URL или 11-символьный YouTube id |
| Типы загрузки | JPEG, PNG, WebP, GIF, MP4, WebM до 25 MB |
| GitHub URL | `raw.githubusercontent.com`, закреплённый на полный SHA коммита |
| Альтернативный текст | обязательно |

Локального превью недостаточно: загрузка должна завершиться до **Сохранить представление**.
YouTube хочет id, не полный URL.

## Совпадающие команды CLI

```bash
ai-stp owner objects --json
ai-stp owner object show --json
ai-stp owner version show --json
ai-stp component discover --json
ai-stp toolchain harnesses --json
ai-stp publication plan --json
ai-stp publication status --json
```

`owner objects` — список. `owner object show` — один объект и его
версии. `owner version show` — один `X.Y` плюс evidence жизненного
цикла. Подтверждение публикации может быть в CLI или на сайте; см.
[Публикацию](publications.md).

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| Пока нет объектов | на сервере ничего не принадлежит вам | discover / publish из CLI |
| Этот объект недоступен вашему аккаунту. | не ваше или неизвестно | не зондируйте id |
| Для объекта нет записанных версий. | никогда не выпускали | `component version release` в CLI |
| Install blocked | eligibility false | читайте evidence; не форсируйте apply |
| Начать публикацию нет | не разрешено, нет CSRF или нет устройства | привяжите CLI-устройство; `publication plan` |
| Media upload failed | тип/размер/источник | исправьте элемент; не Save посреди загрузки |
| Публичная страница 404 | не опубликовано / не видно | ожидаемо для частных черновиков |
| External services скрыты | флаг выкл. | связи каталога опущены |
