# Издатели

Страница издателя — публичное лицо одного аккаунта: display name, bio,
HTTPS-ссылки, аватар, `author_verified` и объекты этого аккаунта в
каталоге. Это не паспорт, не гарантия доверия и не частный профиль.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human | `/{locale}/publishers/{account_id}` | всем |
| Machine | `/{locale}/ai/publishers/{account_id}` | всем |

`{account_id}` — ULID аккаунта, не GitHub-логин и не display name.
Кривой id даёт 404. Корректный id без публичной проекции тоже 404:
сайт не подтверждает, что аккаунт существует.

Опубликованную страницу может читать кто угодно. Владелец, войдя на
свой id, видит **Редактировать публичный профиль** на
`/{locale}/account/profile`.
Посетители — нет.

Флаги приватности на [Аккаунте](account.md) решают, показывается ли
богатый профиль вообще. `Show profile publicly` и `Allow publisher
listing` разделены. Пустая публичная проекция всё равно перечисляет
**опубликованные объекты**, если они есть в каталоге.

## Зачем этот экран

Страница нужна, чтобы:

- увидеть, кто публикует объект каталога (из колонки автора);
- прочитать короткое bio и до восьми HTTPS-ссылок;
- просмотреть публичные компоненты и сетапы этого аккаунта, включая
  experimental;
- скопировать CLI deep link издателя.

Страница **не**:

- верифицирует содержимое (`author_verified` — идентичность, не безопасность);
- показывает частные или unlisted объекты;
- даёт follow, сообщение или звезду издателю;
- сливает идентичности GitHub и Google (это Account);
- меняет `component_verified` любой версии.

## Что на экране

**Назад в каталог** возвращает в каталог с включённым experimental.

| Элемент | Содержимое |
| --- | --- |
| Avatar | опубликованное изображение или инициалы из display name / id |
| Title | display name или слово **Издатель**, если пусто |
| Badge | **Автор подтверждён**, когда `author_verified` истинно |
| Account id | моноширинный, копируется как текст |
| CLI copy | каноническая команда `link web` для этого издателя |
| Links | label + hostname, `rel=noopener`, только HTTPS |
| Bio | ограниченный Markdown (списки, заголовки, emoji, таблицы, ссылки, жирный, код) |
| Редактировать публичный профиль | только владельцу |
| Публичный профиль | когда проекция не пуста |

Текст пустой проекции:

> У этого издателя нет публичного профиля. Показаны только идентификатор аккаунта и опубликованные объекты.

### Опубликованные объекты

Две группы, карточки каталога:

| Группа | Источник |
| --- | --- |
| Компоненты | поиск с `authors=[account_id]`, experimental включён |
| Сетапы | то же для сетапов |

Каждая карточка обычная: kind, version, harness, два бита verified,
лайки. Отдельной полки «unlisted» нет. Объекты, которыми аккаунт
владеет, но не опубликовал, не появляются; они живут в
[Объектах](objects.md) у владельца.

Пустая группа: **Публичных объектов нет.**

Human / Machine сохраняет account id. Machine-проекция печатает
`account_id`, `author_verified`, `display_name`, `bio` и списки
объектов ссылками.

## Совпадающие команды CLI

```bash
ai-stp link web --json
ai-stp registry search --json
ai-stp registry show --kind component --id <stable_id> --json
ai-stp registry show --kind setup --id <stable_id> --json
ai-stp owner objects --json
```

`link web` — то, что страница копирует для цели издателя. `registry
search` с ограничением по автору — CLI-эквивалент списков объектов.
`owner objects` — **ваши** объекты после входа; чужой частный граф так
не выгрузить.

Команды `ai-stp publisher` нет.

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| `Page not found` | плохой id или нет публичной проекции | откройте автора с карточки каталога |
| Пустой текст профиля | издатель не опубликовал bio | используйте только account id + объекты |
| No public objects listed | в каталоге ничего у этого автора | не делайте вывод о скрытом инвентаре |
| Автор подтверждён, проверки не прошли | идентичность ≠ содержимое | читайте карточку компонента |
| Edit public profile нет | вы не этот аккаунт | ожидаемо |
| Браузер отказал ссылке | не HTTPS или небезопасный URI | редактор профиля отвергает их на save |
| 404 после снятия профиля | флаг приватности или пустая редакция | карточки каталога всё равно называют id |

Карточка каталога может показать издателя, даже когда эта страница
пуста. Id достаточно для поиска. Отсутствующее bio — не отсутствующий
автор.

## Как объекты сюда попадают

Списки — поиски каталога с `authors=[account_id]` и
`include_experimental=true`. Частные версии владельца никогда не
появляются. Experimental-объекты идут с той же семантикой Main /
Experimental, что в каталоге, но переключателя experimental на этой
странице нет: если объект достаточно публичен для поиска, он в списке.

`author_verified` в шапке — про издателя. Каждая карточка всё равно
показывает свой `component_verified`. Верифицированный издатель с
проваленным пином — обычный случай, чтобы замедлиться, а не
противоречие.

**Редактировать публичный профиль** только у владельца — единственная запись.
Лайки и жалобы на карточках ведут себя как в каталоге (нужна сессия).

Machine publisher документирует `account_id`, `author_verified`,
`display_name`, `bio`, затем ссылки на компоненты и сетапы. Агент не
должен выводить email или GitHub-логин из id.
