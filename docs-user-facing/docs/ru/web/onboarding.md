# Онбординг

Онбординг — шлюз, который встречает новый аккаунт после первого
успешного OAuth. Нужно принять текущие редакции **правил сервиса** и
**«Согласия на обработку персональных данных»**, иначе **Аккаунт**,
**Объекты**, **Устройства** и любые другие закрытые страницы не
откроются.

Это не тур по продукту. Это не необязательный текст.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human | `/{locale}/onboarding` | вошедшим, `onboarding_pending` |
| Machine | `/{locale}/ai/onboarding` | та же ожидающая сессия |

`returnTo` должен начинаться с `/{locale}/`. Иначе подменяется на
`/{locale}/account`.

`requireSession` на каждой закрытой странице перенаправляет сюда, пока
статус аккаунта `onboarding_pending`. `requireOnboardingSession` на
этой странице уводит **прочь** на `returnTo`, как только аккаунт
`active`. Вышедших отправляют на login.

`reason=required` показывает красную заметку: оба подтверждения
обязательны.

## Зачем этот экран

Онбординг фиксирует, что вы прочитали две точные редакции политик и
соглашаетесь на обработку, которую они описывают.

Аккаунт хранит id редакций и время принятия. Отозвать согласие позже
можно удалением аккаунта (не снятием галочки здесь задним числом).

Онбординг **не**:

- публикует профиль;
- привязывает CLI-устройство (это после, на [Устройствах](devices.md));
- позволяет пропустить любую из галочек;
- принимает «какая политика сейчас актуальная» без закрепления id;
- появляется в self-hosted сборках, которые не создают SaaS-аккаунты
  тем же путём — если вы его не видите, вы не в этом шлюзе.

## Что на экране

Заголовок: **Перед продолжением.** Текст: ознакомьтесь с текущими
правилами сервиса и подтвердите обработку данных, необходимую для
работы аккаунта.

| Элемент | Подпись | Закреплённая редакция |
| --- | --- | --- |
| Checkbox 1 | Я ознакомился и принимаю правила сервиса. | `service_rules_revision_id` |
| Checkbox 2 | Я согласен с обработкой данных, описанной в документе «Согласие на обработку персональных данных». | `personal_data_consent_revision_id` |
| Submit | Продолжить | оба обязательны |

Ссылка на правила сервиса —
`/{locale}/legal/service-rules?revision={id}`. Согласие на обработку
персональных данных —
`/{locale}/legal/personal-data-consent?revision={id}`. Заголовки самих
правовых страниц в русской locale остаются как в UI: `Service rules` и
«Согласие на обработку персональных данных». Без query эти страницы
показывают текущую публичную редакцию, которая в момент регистрации
должна совпадать.

Предложение в подвале:

> В аккаунте сохраняются точная редакция документа и время
> подтверждения. Согласие можно отозвать удалением аккаунта.

Human / Machine: machine Onboarding — заголовок и абзац. Галочки
только human.

## Совпадающие команды CLI

Онбординга в CLI нет. После шлюза:

```bash
ai-stp auth status --json
ai-stp auth login --provider github --json
ai-stp device init --json
```

`auth status` должен уйти с ожидающей связи, когда принятие на сайте
сохранено и CLI-сессия завершена. Не пытайтесь POST-ить правовое
принятие из оболочки; id редакций закреплены в этой форме.

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| Для создания аккаунта нужны оба подтверждения. | отправили с выключенной галочкой | отметьте обе |
| Цикл редиректа на onboarding | принятие не записалось | повторите; проверьте доступность API |
| Сразу редирект на account | уже `active` | готово |
| Редирект на login | нет сессии | войдите, затем онбординг |
| Legal 404 по ссылке | `saas_public_pages` выкл. или плохой id | не выдумывайте slug; повторите регистрацию |
| Хотите поменять галочку позже | это не редактор | читайте [Правовые документы](legal.md); отзыв — удаление аккаунта |
| Облачные вызовы CLI отказаны | онбординг ещё pending | сначала закончите эту страницу |

Не вставляйте персональные данные в соседние поля галочек — их нет.
Не вставляйте текст политики в паспорт.

## Типичный путь

1. [Вход](login.md) через Google или GitHub в первый раз.
2. OAuth callback создаёт аккаунт в `onboarding_pending`.
3. Каждый закрытый URL возвращает сюда, пока Continue не сработает.
4. Отметьте обе галочки. Откройте ссылки с закреплённой редакцией,
   если ещё не читали.
5. Continue сохраняет два id редакций и время.
6. Вы попадаете на `returnTo` (по умолчанию Account).

Выбор cookie (analytics / marketing) — **другой** баннер. Это не эти
две галочки. Снятие analytics позже не отзывает согласие на
персональные данные; это делает удаление аккаунта.

## Чем этот шлюз не является

| Поверхность | Путают с онбордингом? | Разница |
| --- | --- | --- |
| Баннер cookie | иногда | необязательные категории; не создание аккаунта |
| Публикация профиля | нет | оформление, когда уже `active` |
| Одобрение устройства | нет | привязка CLI-устройства к уже активному аккаунту |
| Catalog experimental | нет | согласие на объекты, не на оператора |

Если политику пересмотрят после принятия, ваши сохранённые id остаются
теми редакциями, которые вы видели. Продукт не перепривязывает вас
молча к новому хешу с этой страницы.

Continue — один POST обеих отметок. Очереди «принять позже» нет.
Закрытие вкладки оставляет аккаунт pending: следующий закрытый URL
вернёт сюда.
