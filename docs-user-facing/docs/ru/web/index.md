# Веб

Сайт — это публичный каталог и аккаунт. Он показывает сетапы и
компоненты, страницы издателей, правовые редакции и рабочее
пространство после входа. Он не собирает сетап, не пишет target
харнесса и не вызывает модель.

Рабочая поверхность выбора, проверок и установки — CLI плюс
provider харнесса. Читайте каталог здесь; применяйте план там.

```text
Website → доказательства каталога, аккаунт, confirm публикации
CLI     → паспорта, select, план установки
Provider → нативное состояние харнесса
```

## URL и кто их видит

У каждой страницы две проекции одних и тех же фактов. `{locale}` —
это `en` или `ru`.

| Проекция | Шаблон | Для кого |
| --- | --- | --- |
| Human | `/{locale}/…` | человек в браузере |
| Machine | `/{locale}/ai/…` | агент, читающий Markdown |

Фиксированный переключатель **Human** / **Machine** внизу окна
сохраняет путь, query string и locale. Он не меняет доступ: частный
machine URL всё равно требует ту же session cookie, что и human-пара.

Анонимные посетители могут открыть Главную, Каталог, Региональные
сервисы, Издателей, Материалы (когда включён `content_hub`), этот
справочник, Контакт и Правовые документы (когда включён
`saas_public_pages`), и Вход. Вошедшие дополнительно получают
Аккаунт, Профиль, Устройства, Объекты, Доступ, Жалобы, Лайки,
Онбординг и планы публикации.

Запрос без сессии к частному URL отправляется на
`/{locale}/login?returnTo=…`. Сначала истекшая cookie очищается, и
посетитель попадает на вход с `reason=session_expired`. Новый аккаунт
с `onboarding_pending` направляется на Онбординг раньше любой другой
частной страницы.

## Для чего эта поверхность

Сайт нужен, чтобы:

- установить CLI командой с лендинга;
- искать публичный каталог и читать паспорт;
- лайкать, делиться или жаловаться на опубликованную версию;
- войти через Google или GitHub и привязать CLI-устройство;
- править публичный профиль и флаги приватности;
- подтвердить план публикации, который CLI уже собрал;
- пригласить или отозвать доступ к major-линии;
- подать жалобу на точный digest версии.

Сайт **не** нужен, чтобы:

- собирать, закреплять или применять сетап;
- писать файлы в Claude Code, Codex, Grok Build или любой другой
  харнесс;
- запускать сканеры безопасности (они работают при публикации, не в
  браузере);
- сливать два аккаунта;
- открывать staff-модерацию (`/staff/reports` — не пользовательская
  страница).

## Что есть на каждом экране

Human-шапка липкая. В ней всегда Главная (знак `ai_stp`), Каталог,
Региональные сервисы и Документация. Документация — **внешняя**
ссылка: MkDocs-справочник из `AI_STP_USER_DOCS_URL` (в разработке
`http://localhost:8011`). Она не переписывается в проекцию.

Когда скомпилирован `content_hub`, в шапке появляется Материалы.
Когда скомпилирован `saas_public_pages`, появляется Контакт
(клавиша `C`). После входа Объекты, Доступ, Жалобы и Устройства
переезжают в меню аккаунта вместе с Профилем, Моими лайками и Выйти.
Клавиша `P` открывает Аккаунт или Вход. `Ctrl`/`Cmd` `K` фокусирует
поиск каталога, когда открыта эта страница.

Подвал повторяет Каталог, Региональные сервисы, Документацию и
Материалы, затем (в публичном SaaS-профиле) Контакт,
Конфиденциальность, Файлы cookie, Правила сервиса и Лицензирование.
`llms.txt` — машинный индекс, не статья справочника.

Тема (светлая / тёмная / системная) и locale (`en` ↔ `ru`) живут в
шапке. Locale меняет только префикс пути; идентификаторы, имена
полей, токены Catalog QL и команды CLI остаются латиницей.

Machine-шапка рендерит ту же навигацию как Markdown-ссылки плюс
`llms.txt` и locale `<select>`. Клавиши печатаются в machine-подвале.

## Флаги функций

Публичный SaaS-профиль включает `content_hub` и `saas_public_pages`.
Self-hosted профиль выключает оба: Материалы, Контакт и правовые
колонки подвала исчезают. Каталог, аккаунт и путь CLI остаются.

| Страница справки | Human URL | Кому видно | Что это |
| --- | --- | --- | --- |
| [Главная](home.md) | `/{locale}/` | всем | лендинг, установка CLI, вход в каталог |
| [Каталог](catalog.md) | `/{locale}/catalog` | всем | поиск, Catalog QL, Both-режим |
| [Карточка компонента](catalog-component.md) | `/{locale}/catalog/components/{stable_id}` | всем | один публичный компонент |
| [Карточка сетапа](catalog-setup.md) | `/{locale}/catalog/setups/{stable_id}` | всем | один публичный сетап и его пины |
| [Региональные сервисы](services.md) | `/{locale}/services` | всем | атлас СНГ во фильтры каталога |
| [Издатели](publishers.md) | `/{locale}/publishers/{account_id}` | всем | публичная страница издателя |
| [Материалы](content.md) | `/{locale}/content` | всем, если флаг | статьи и заметки |
| [Эта документация](docs.md) | хост MkDocs и `/{locale}/docs` | всем | этот справочник |
| [Контакт](contact.md) | `/{locale}/contact` | всем, если флаг | сохранённое сообщение, без секретов |
| [Правовые документы](legal.md) | `/{locale}/legal/{slug}` | всем, если флаг | версионированные политики |
| [Вход](login.md) | `/{locale}/login` | всем | OAuth и device code |
| [Аккаунт](account.md) | `/{locale}/account` | после входа | id, идентичности, приватность |
| [Профиль](profile.md) | `/{locale}/account/profile` | после входа | публичное отображение, не паспорт |
| [Устройства](devices.md) | `/{locale}/devices` | после входа | браузеры и установки CLI |
| [Объекты](objects.md) | `/{locale}/objects` | после входа | свои компоненты и сетапы |
| [Доступ](access.md) | `/{locale}/access` | после входа | приглашения и гранты |
| [Жалобы](reports.md) | `/{locale}/reports` | после входа | ваши case, не staff-очередь |
| [Лайки](likes.md) | `/{locale}/likes` | после входа | сохранённые объекты каталога |
| [Онбординг](onboarding.md) | `/{locale}/onboarding` | pending-аккаунт | правила сервиса и согласие |
| [Публикация](publications.md) | `/{locale}/publications/{plan_id}` | после входа | подтвердить план, собранный CLI |

Страницы точных версий висят на объекте, которому принадлежат:

- `/{locale}/catalog/components/{stable_id}/versions/{version}`
- `/{locale}/catalog/setups/{stable_id}/versions/{version}`
- `/{locale}/objects/{kind}/{stable_id}/versions/{version}`

Страницы страны и сервиса висят на Региональных сервисах:

- `/{locale}/countries/{code}`
- `/{locale}/services/{canonical_domain}`

Одобрение устройства также живёт по адресу `/{locale}/device-login`.
Принятие приглашения — `/{locale}/invitations/{invitation_id}`.
Превью профиля — `/{locale}/account/profile/preview`. Приватность —
`/{locale}/account/privacy`. Правка презентации —
`/{locale}/objects/component/{stable_id}/edit`.

Эти дополнительные URL описаны на страницах разделов выше. Отдельных
глав справочника у них нет.

## Соответствующие команды CLI

Сайт копирует только команды, которые CLI реально разбирает.
Канонические шаблоны:

```bash
uv tool install ai-stp-cli
ai-stp auth login --provider github --json
ai-stp registry search --json
ai-stp registry show --kind component --id <stable_id> --json
ai-stp registry version --kind component --id <stable_id> --version <x.y> --json
ai-stp link web --json
```

Полная карта — [карта команд](../cli/commands.md). Если эта страница
и `ai-stp help --agent --json` расходятся, следуйте CLI.

## Тупики, которые действуют везде

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| `Страница не найдена` | неизвестный путь, черновик или id, который каталог не публикует | открыть [Каталог](catalog.md) или Главную |
| `Сервис временно недоступен` | API не ответил | повторить позже; локальный кэш CLI может ещё читать |
| `Сессия истекла` | HttpOnly cookie исчезла или устарела | войти снова; `returnTo` сохраняется |
| пустой список | типизированный ноль, не сбой | сменить фильтры, опубликовать из CLI или лайкнуть объект |
| нет Материалов или Контакта | скомпилированный профиль выключил флаг | пользуйтесь Каталогом и CLI; на self-hosted это ожидаемо |

404 никогда не говорит, частный объект, черновик он или отсутствует.
