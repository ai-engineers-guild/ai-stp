# Каталог

Каталог — публичный индекс сетапов и компонентов. Читать его может
кто угодно. Он не устанавливает, не собирает и не закрепляет пины.
Карточка — доказательство для позднего решения в CLI.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human | `/{locale}/catalog` | всем |
| Machine | `/{locale}/ai/catalog` | всем |

Query string сохраняется при переключении Human / Machine. Неизвестные
ключи не игнорируются молча: страница показывает
`Некорректный фильтр каталога` вместо тихого отбрасывания.

Запрос по умолчанию, когда страница открыта без параметров:

- `resource=all` (Оба);
- `include_experimental=1` (экспериментальные объекты в списке);
- `sort=relevance`, `sort_direction=desc`;
- `view=list`;
- `page_size=25`.

Лайки на карточках требуют сессии. Поиск, фильтры и чтение паспорта —
нет.

## Для чего этот экран

Каталог нужен, чтобы найти кандидата, прочитать оси доверия и
скопировать CLI-команду show/version.

Каталог **не**:

- запускает `select` или `install`;
- пишет план provider;
- считает `author_verified` доказательством, что версия безопасна;
- прячет экспериментальные объекты, пока вы сами не выключите фильтр;
- выдумывает теги вне словаря.

Both-режим показывает **сначала сетапы, затем компоненты**. Каждая
группа сохраняет выбранную сортировку. Пагинация в Both сначала идёт
по страницам сетапов, затем по страницам компонентов.

## Что на экране

### Поиск и Catalog QL

Плейсхолдер поля поиска — `Поиск компонентов и сетапов`. Клавиша
`Ctrl`/`Cmd` `K` ставит фокус. Текст справки:

> Ищите обычными словами или на Catalog QL: поля NAME, TAGS, HARNESS,
> TYPE, AUTHOR и VERIFIED; операторы :, AND, OR, NOT, IN, NOT IN и
> скобки. Пример:
> `TYPE:skill AND HARNESS IN (codex, claude-code)`.

| Форма | Смысл |
| --- | --- |
| обычные слова | полнотекстовый термин |
| `FIELD:value` | равенство по полю из allowlist |
| `FIELD IN (a, b)` | принадлежность |
| `FIELD NOT IN (a, b)` | исключение |
| `AND` / `OR` / `NOT` | булевы связки |
| `( … )` | группировка, глубина ограничена |

Поля allowlist: `NAME`, `TAGS`, `HARNESS`, `TYPE`, `AUTHOR`,
`VERIFIED`. Запрос длиннее 500 символов, слишком много токенов или
неизвестное поле отклоняются на границе API. Структурные фильтры
формы соединяются с AST QL через `AND`.

`Возможно, вы имели в виду` может предложить исправление. Оно не
запускается, пока вы его не примете.

### Ресурс, экспериментальные, раскладка

| Элемент | Значения | По умолчанию |
| --- | --- | --- |
| Тип ресурса каталога | Оба / Сетапы / Компоненты | Оба |
| Показать экспериментальные | вкл / выкл | вкл |
| Вид выдачи | Карточки / Список | Список |
| Сортировка выдачи | По релевантности / По времени обновления / По числу лайков | По релевантности |
| Направление | По возрастанию / По убыванию | По убыванию |

Основные объекты помечены **Основные** (`authoritative`).
Экспериментальные — **Экспериментальные**. Примечание под выдачей:

> Основные и экспериментальные объекты показаны вместе. Подтверждение
> автора не доказывает безопасность содержимого.

Выключение экспериментальных прячет эту полосу только для этого
поиска. Это не запись согласия для позднего `select`.

### Фильтры

**Фильтры и сортировка** открывает панель. **Применить фильтры**
записывает query string. **Сбросить всё** возвращает значения по
умолчанию выше.

| Фильтр | Ключ запроса | Что оставляет |
| --- | --- | --- |
| Тег | `tags` | теги словаря (неверные id — ошибка) |
| Упряжка | `harness_id` / `harness_ids` | паспорта, которые называют этот харнесс |
| Тип компонента | `component_type` / `component_types` | `instruction`, `skill`, `mcp`, `hook`, `command`, `agent`, `plugin`, `setting` |
| Автор | `authors` | id аккаунтов издателей, через запятую |
| Только проверенные | `verified_only` | оба `author_verified` и `component_verified` текущие |
| Страны | `country_code` / `country_codes` | связанные рынки; **Не задано** — нет списка стран |
| Региональные сервисы | `service_domain` / `service_domains` | связанные сервисы; список следует за выбранными странами |
| Обновлено с / по | `updated_from` / `updated_to` | включительные даты обновления в каталоге |
| Уровень поддержки | `support_tier` | `primary` или `beta` |
| Состояние поддержки | `support_state` | `verified`, `stale`, `missing`, `not_verified` |

Чипы в строке поиска снимают один фильтр. Неизвестные ключи,
неверные теги, неверные значения поддержки или сломанная строка QL
дают `Некорректный фильтр каталога` с причиной. Они никогда не
вызывают поиск.

### Карточки выдачи

Каждая карточка показывает вид (Сетап или тип компонента), имя,
версию, бейджи харнесса, теги, издателя, `author_verified`,
`component_verified`, лайки и сводку безопасности, когда проверки
есть.

`author_verified` и `component_verified` **независимы**.
Подтверждённый автор всё равно может опубликовать неподтверждённую
версию. Фильтр verified требует оба.

Дополнительные действия на карточке:

| Действие | Нужна сессия | Эффект |
| --- | --- | --- |
| Скопировать URL | нет | буфер обмена |
| Скопировать ID | нет | `stable_id` |
| Скопировать CLI-команду | нет | `ai-stp registry version --kind … --id … --version …` |
| Нравится / Не нравится | да | сохраняется в [Лайки](likes.md) |
| Пожаловаться | да | открывает [Жалобы](reports.md) с kind, id, version, digest |

Пустая выдача:

| Ресурс | Заголовок пустоты |
| --- | --- |
| Оба | Нет объектов каталога по этому запросу. |
| Сетапы | Нет сетапов по этому запросу. |
| Компоненты | Нет компонентов по этому запросу. |
| Только основные | Нет основных результатов по этому запросу. |

Метрики использования (просмотры страницы, скачивания артефакта)
появляются, когда скомпилирован `catalog_usage_metrics`. Это счётчики,
не сигнал безопасности.

## Соответствующие команды CLI

Анонимные чтения каталога:

```bash
ai-stp registry search --json
ai-stp registry show --kind component --id <stable_id> --json
ai-stp registry show --kind setup --id <stable_id> --json
ai-stp registry version --kind component --id <stable_id> --version <x.y> --json
ai-stp registry version --kind setup --id <stable_id> --version <x.y> --json
```

`registry search` — CLI-близнец этой страницы. `registry show` — объект.
`registry version` — один неизменяемый `X.Y`. Забрать в локальный кэш —
другая команда:

```bash
ai-stp registry fetch --json
```

Канонический URL сайта для объекта:

```bash
ai-stp link web --json
```

Выбор и установка — **не** команды каталога. Они начинаются с
[Выбора](../cli/select.md) и [Установки](../cli/install.md).

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| Некорректный фильтр каталога | неизвестный ключ, плохой тег, плохой QL | уберите неизвестный параметр; почините QL |
| Нет объектов каталога | типизированная пустота | расширьте фильтры; оставьте экспериментальные включёнными |
| Сервис временно недоступен | API лежит | повторите; кэш CLI может ещё `registry show` |
| Лайк визуально ничего не делает | нет сессии | [Войти](login.md), затем лайкнуть снова |
| В форме жалобы нет полей | вы открыли её не с версии | откройте карточку, затем Пожаловаться |
| Страница Both-режима выглядит как только сетапы | вы ещё на странице сетапов смешанного пейджера | идите вперёд мимо страниц сетапов |
| Карточка 404 после клика | снято с публикации, заблокировано или неизвестный id | оставайтесь в поиске; не угадывайте id |

Machine-документ каталога перечисляет активный запрос полями, затем
сетапы и компоненты. Пустой machine-вывод — то же пустое сообщение,
не stack trace.
