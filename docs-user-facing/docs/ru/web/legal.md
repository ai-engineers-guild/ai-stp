# Правовые документы

Правовые страницы — версионированные политики хостингового сервиса.
Каждый документ — неизменяемая редакция: заголовок, `policy_version`,
`effective_at`, locale и HTML, отрендеренный из исходного Markdown.

Это не SPDX-лицензии компонентов, не строка AGPL в подвале и не
changelog хаба материалов.

## URL и кто их видит

| Проекция | URL | Кому видно |
| --- | --- | --- |
| Human | `/{locale}/legal/{slug}` | всем, если флаг |
| Machine | `/{locale}/ai/legal/{slug}` | всем, если флаг |

`{slug}` — одно из:

| Slug | Заголовок на сайте |
| --- | --- |
| `privacy` | Privacy |
| `cookies` | Cookies |
| `service-rules` | Service rules |
| `personal-data-consent` | Согласие на обработку персональных данных |
| `licensing` | Licensing / author content responsibility |

Любой другой slug даёт 404. Необязательный `?revision=` закрепляет
аудиторскую редакцию. Без него показывается текущая публичная
редакция.

Эти маршруты существуют, когда включён `saas_public_pages` (публичный
SaaS-профиль). Self-hosted опускает правовые колонки подвала. UI
согласия на cookies всё равно можно скомпилировать отдельно.

Политику может читать кто угодно. Принятие **Правил сервиса** и
**Согласия на обработку персональных данных** новым аккаунтом —
[Онбординг](onboarding.md), который сохраняет точные id редакций.

Ссылки подвала (SaaS): Конфиденциальность, Файлы cookie, Правила
сервиса, Лицензирование. Онбординг также ссылается на Согласие на
обработку персональных данных.

## Для чего этот экран

Правовые документы нужны, чтобы читать правила оператора: какие
персональные данные обрабатываются, как классифицируются cookies, что
сервис разрешает, за что авторы остаются ответственны.

Поле **Лицензия** карточки компонента — SPDX этой версии. Строка
`AGPL-3.0-or-later` в подвале — ПО `ai_stp`. Эти три слоя друг друга
не заменяют.

Правовые документы **не**:

- собирают новую подпись на каждом визите (онбординг делает это один
  раз на требуемую редакцию);
- позволяют править HTML политики;
- показывают лицензии авторов объектов каталога;
- сами включают аналитику (выбор cookies — отдельный баннер).

## Что на экране

Левый рельс: **На главную**, затем **Документы** с пятью slug.
Текущий slug помечен `aria-current="page"`.

Основная колонка:

| Элемент | Содержимое |
| --- | --- |
| Заголовок | заголовок политики из редакции |
| Примечание | Это текущая публичная редакция. Human- и machine-представления содержат одинаковые правовые факты. |
| Версия | `policy_version` |
| Вступает в силу | дата `effective_at` или тире |
| Язык | `en` или `ru` |
| Исходный Markdown на GitHub | blob URL файла под `docs-user-facing/legal/…` |
| Текст документа | отрендеренный HTML |

Переключатель Human / Machine сохраняет slug и query `revision`.
Machine-правовое печатает ту же версию, дату вступления в силу и
locale полями, затем текст.

Баннер cookies (когда включён) — не эта страница. Он предлагает
Необходимые (всегда включены), Аналитика, Маркетинг, Принять все,
Отклонить необязательные, Сохранить выбор. **Политика
конфиденциальности** в этом баннере ссылается сюда на `privacy`.
**Приватность** аккаунта также предлагает **Настройки cookies**.

## Соответствующие команды CLI

Правового CLI нет. Принятие онбординга — POST сайта. Выбор cookies —
POST сайта.

Флаги приватности после входа (видимость профиля) живут в Аккаунте,
не здесь:

```bash
ai-stp auth status --json
ai-stp link web --json
```

`auth status` говорит, есть ли у устройства сессия аккаунта. HTML
политики он не печатает.

## Тупики

| Что видно | Что это значит | Что делать |
| --- | --- | --- |
| Правовое 404 | неизвестный slug или страниц нет в этом профиле | используйте пять slug выше |
| `revision` 404 | эта редакция не публичная | уберите query, чтобы увидеть текущую |
| В подвале нет правовой колонки | `saas_public_pages` выключен | читайте `LICENSE` репозитория и локальную политику |
| SPDX на карточке ≠ эта страница | лицензия автора vs политика оператора | читайте оба; они отвечают на разные вопросы |
| Онбординг всё ещё блокирует | вы не приняли закреплённые редакции | откройте [Онбординг](onboarding.md) |
| Баннер cookies возвращается | необязательные категории не заданы | Принять, Отклонить или Сохранить выбор |

Не вставляйте персональные данные в ссылку правки GitHub, «чтобы
исправить политику». Источник ревьюится в репозитории как любой
другой файл.

## Три слоя лицензий

| Слой | Где читать | Что покрывает |
| --- | --- | --- |
| Политики оператора | эта глава | хостинговый сервис, персональные данные, cookies |
| ПО `ai_stp` | подвал `AGPL-3.0-or-later` | код продукта |
| Объект автора | **Лицензия** каталога (SPDX) | эта версия компонента или сетапа |

`licensing` на этом сайте — ответственность за авторский контент
хостингового каталога, не вторая копия AGPL. Компонент MIT всё равно
отдаётся по правилам сервиса оператора.

Онбординг закрепляет только `service-rules` и
`personal-data-consent`. Конфиденциальность и cookies читаются без
чекбокса. Смена категорий cookies не переписывает эти Markdown-
редакции.

Machine-правовое — те же факты: версия, дата вступления в силу,
locale, тело. Агент должен цитировать `policy_version` и `revision`,
а не пересказывать запомненную оговорку.
