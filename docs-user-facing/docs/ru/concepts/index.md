# Понятия

Это слова, которые `ai_stp` использует в одном значении каждое. Если в одном
предложении два из них ведут себя как один объект, предложение неверно.

## Харнесс

Харнесс — CLI-среда, в которой работает coding agent. `ai_stp` не заменяет
её и не вызывает модели.

Основная поддержка: Claude Code, Codex, Grok Build. Beta: Pi, OpenCode,
Cursor, Antigravity. Неизвестный харнесс: ограниченный `undefined`.

Подробнее: [поддерживаемые харнессы](../harnesses.md).

## Сетап

Сетап — полная конфигурация одного харнесса. Он принадлежит этому харнессу с
момента создания и закрепляет точные версии компонентов.

Любое изменение состава создаёт новую версию сетапа. Версии имеют вид `X.Y`,
а не SemVer: патч-номера нет, опубликованный `X.Y` неизменяем.

Подробнее: [сетапы](../setups/index.md).

## Компонент

Компонент — отдельная часть сетапа одного из восьми видов. Память, правила,
параметры и вспомогательные инструменты являются *содержимым* `instruction`,
`skill` или `setting`, а не отдельными видами.

Восемь видов и как между ними выбирать — на странице
[виды компонентов](../components/index.md). Эта страница список не
повторяет.

## Provider и сборщик

Два разных объекта делают две разные работы.

**Сборщик сетапа** — детерминированный слой `ai_stp`. Он проверяет граф
компонентов, отклоняет несовместимости и создаёт нативный пакет для
provider. Он не пишет файлы харнесса.

**Provider** — публичный менеджер сетапа NDDev для этого харнесса. Только он
пишет итоговое состояние харнесса. Перед записью он строит план. После
записи он фиксирует status, который `ai_stp` может прочитать.

Если эти две роли сливаются в фразу «ai_stp установил файлы», путь установки
описан неверно. `ai_stp` спланировал и собрал; provider применил.

## Паспорт

Паспорт — версионируемое машиночитаемое описание объекта. Через паспорта
`ai_stp` связывает происхождение, совместимость, ограничения и результаты
проверок.

В паспорт не попадают секреты, содержимое `.env`, токены и приватные пути.

## Линия доверия

Линия доверия определяет, как объект попадает в выдачу:

- `authoritative`;
- `experimental`;
- `local_owner_or_pinned`.

Непроверенный объект не участвует в автоматической установке без явного
согласия пользователя.

`author_verified` и `component_verified` — независимые оси. Одно не следует
из другого.

Подробнее: [доверие и безопасность](../trust-and-safety/index.md).

## План, связанный digest

Любая запись, которая может изменить target, публикацию или локальную
версию, начинается с плана. У плана есть digest. Apply повторяет вычисление
и отказывается, если digest больше не совпадает.

Типичные токены:

- `--expected-plan-digest` для scaffold, обновления паспорта, compose,
  подтверждения установки и импорта сетапа;
- `--plan-hash` для плана публикации;
- `--set-digest` для набора публикации сетапа;
- `--confirm`, когда вид подтверждения — явный флаг.

Устаревший digest — не подсказка «протолкнуть старый план». Постройте новый
план и подтвердите его. См. [диагностику](../troubleshooting/index.md).

## Три режима

`ai_stp` работает в трёх пересекающихся режимах. Это не редакции продукта.

=== "Локальный"

    Достаточно идентичности устройства и паспорта разработчика. Можно
    обнаруживать нативные компоненты, принимать их, собирать сетап из
    локальных и закреплённых источников и просить provider применить
    изменения — без аккаунта.

    ```bash
    ai-stp device init --json
    ai-stp passport developer init --json
    ai-stp doctor --json
    ```

=== "Анонимный"

    Публичный каталог читается без входа. Search, show и version — это чтение
    каталога. Они не выдают доступ, не публикуют и не синхронизируют.

    ```bash
    ai-stp registry search --kind setup --query frontend --json
    ai-stp registry show --kind setup --id <stable_id> --json
    ```

=== "Со входом"

    Аккаунт нужен для публикации, синхронизации, grants, объектов владельца
    и привязки устройства к облачной сессии.

    ```bash
    ai-stp auth login --provider github --json
    ai-stp auth status --json
    ```

Локальная работа остаётся локальной, пока вы не публикуете и не
синхронизируете. Анонимное чтение каталога никогда не становится сессией.
Вход сам по себе ничего не устанавливает.

## Устройство

Устройство — идентичность этой установки: стабильный идентификатор и ключ
подписи. Закрытый ключ лежит в системном хранилище секретов, если есть
доверенный backend, иначе — в файле только для владельца. `doctor` называет
уровень. Нет тихого fallback, который выдаёт plaintext-файл за связку ключей.

```bash
ai-stp device init --json
ai-stp device show --json
```

`device reset` разрушителен, требует `--confirm` и не является способом
повторить `doctor`. Подробности: [Устройство](../cli/device.md).

## Проект

Проект — один проиндексированный корень. `ai_stp` обнаруживает его,
индексирует без чтения секретов и двоичного содержимого и может записать
паспорт проекта, который закрепляет индекс, toolchain и конфигурацию.

```bash
ai-stp project discover --root . --json
ai-stp project index --root . --json
ai-stp project passport --root . --json
```

Сетап устанавливается в пару проект-харнесс. Status, diff, резервные копии и
именованный откат этой пары — команды [target](../cli/target.md).

Подробности: [Проект](../cli/project.md).
