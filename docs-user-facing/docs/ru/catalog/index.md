# Каталог

Публичный каталог помогает найти сетапы и компоненты по харнессу, тегам,
совместимости, дате обновления и линии доверия. Режим Both сначала показывает
сетапы, затем компоненты; каждая группа сохраняет выбранную сортировку.

Веб показывает карточки. CLI ищет, показывает версии и забирает те же
публичные объекты. Ни одна из поверхностей ничего не устанавливает:
установка — отдельный provider-план, связанный digest.

Карточки веба: [Каталог веба](../web/catalog.md). Что означает результат
сканирования: [Проверки безопасности](../security-checks.md).

## Анонимное чтение

Читать публичный каталог можно без аккаунта. Это нужно для первого знакомства,
локального подбора и работы агента до авторизации.

```bash
ai-stp registry search --kind setup --query frontend --json
ai-stp registry search --kind component --query playwright --json
ai-stp registry show --kind setup --id <stable_id> --json
ai-stp registry version --kind setup --id <stable_id> --version 1.0 --json
```

`--kind` обязателен: `setup` или `component`. В CLI нет одного смешанного
поиска; режим Both — веб-выдача, которая склеивает две половины.

Экспериментальные объекты живут в отдельной секции и требуют явного флага:

```bash
ai-stp registry search --kind component --query scanner --include-experimental --json
```

`--include-experimental` действует только на эту команду. Он не сохраняется и
не является согласием на установку. Согласие — это
[доверие и безопасность](../trust-and-safety/index.md) и
`ai-stp consent allow`.

## Fetch и офлайн-кэш

Search и show могут ответить из кэша, если сеть недоступна. Конверт говорит,
когда платформа последний раз подтвердила байты. Это датированный снимок, а
не живой каталог.

Чтобы закрепить точные опубликованные байты локально:

```bash
ai-stp registry fetch --kind component --id <stable_id> --version 1.0 --json
ai-stp registry acquire --id <setup_id> --version 1.0 --json
ai-stp registry acquire --id <setup_id> --version 1.0 --offline --json
```

`fetch` пишет неизменяемые байты с адресацией по содержимому в локальный кэш.
`acquire` берёт один точный опубликованный граф сетапа для локальной офлайн-
компиляции. `--offline` использует только проверенные кэшированные паспорта
и артефакты.

## Веб и CLI

| Задача | Веб | CLI |
| --- | --- | --- |
| Карточки, Both-режим, сортировка | да | нет смешанного Both-поиска; два поиска с `--kind` |
| Читать публичный объект без аккаунта | да | `registry search` / `show` / `version` |
| Забрать точные байты в локальный кэш | нет | `registry fetch`, `registry acquire` |
| Выбор, сборка, установка | нет | группы select, setup, install |
| Публикация | UI аккаунта плюс CLI confirm | `publication` и `setup publish` |
| Пожаловаться | UI жалобы | `report preview`, затем `report confirm` |

Веб не собирает сетап и не пишет нативное состояние харнесса. Если карточка
выглядит правильно, следующая команда всё равно в CLI.

## Режим Both

В вебе режим Both сначала показывает сетапы, затем компоненты. Каждая группа
сохраняет выбранную сортировку: нет единого смешанного рейтинга, который
скрывает, к какой половине относится объект.

В CLI, если нужны обе половины, запустите два поиска и сами сравните харнесс,
`X.Y`, линию доверия и две оси verified.

## Что смотреть в результате

Перед выбором объекта проверяйте:

- харнесс и поддерживаемую версию;
- точную версию объекта (`X.Y`, а не диапазон);
- происхождение и commit source;
- `author_verified` и `component_verified`;
- линию доверия;
- ограничения совместимости;
- результаты последней проверки, включая процент карточки.

`author_verified` и `component_verified` независимы. Подтверждённый автор не
доказывает безопасность конкретной версии.

| Поле | Что оно отвечает | Красный флаг |
| --- | --- | --- |
| Harness | куда можно применить объект | нужного харнесса нет в списке |
| Version | какая неизменяемая версия выбрана | версия не закреплена точно |
| Source | откуда пришёл объект | нет commit/path или происхождение мутное |
| Trust line | почему объект попал в выдачу | `experimental` без осознанного согласия |
| Verification | что подтвердила платформа | verified только автор, но не компонент |
| Compatibility | какие ограничения есть | beta-харнесс без ручной проверки |
| Checks | какие сканы прошли, провалились или не запускались | высокий процент, скрывающий пропущенные обязательные проверки |

=== "Сетап"
    В сетапе важен полный состав: все компоненты, точные версии и один целевой
    харнесс. Любая замена компонента создаёт новую версию сетапа.

=== "Компонент"
    В компоненте важны вид, область действия и то, как он повлияет на target:
    текстом, tool-доступом, hook-событием, командой или настройкой.

??? question "Почему каталог показывает и человекам, и агентам"
    Человек оценивает смысл, доверие и риск. Agent читает те же факты в
    машинной форме и не должен достраивать missing context из памяти.

## Кэш

CLI может показать объект из локального кэша, если сеть недоступна. Такой ответ
должен указывать момент, когда платформа последний раз подтвердила данные.
Попадание в кэш — не новая verified-публикация.

Смежные страницы команд: [Реестр](../cli/registry.md),
[Выбор](../cli/select.md).
