## Публикация материалов content hub

Content hub хранится в Git. Для каждого материала добавьте по Markdown-файлу в
`docs-user-facing/content/en` и `docs-user-facing/content/ru`. В обоих файлах должны совпадать `type` и
`slug`. Поддерживаются `article`, `blog_post`, `changelog` и `release_notes`.
Неизвестное поле, повтор идентичности, будущая дата, пропущенный перевод или
неверный slug останавливают сборку. `draft: true` исключает материал из
маршрутов, ленты и индексов.

Профиль `AI_STP_WEB_PROFILE=public_saas` включает раздел, а `self_hosted` исключает
его публичную поверхность. Перед публикацией запустите
`bun run test:feature-profiles`.

У каждой публичной страницы материала, контактов или политики есть две равноправные
проекции. Human URL имеет вид `/{locale}/...`, machine URL — `/{locale}/ai/...`.
Закреплённый переключатель Human/Machine сохраняет локаль, текущий маршрут и query
string. Новый публичный маршрут обязан строить обе проекции из одного источника и
сохранять доступность переключателя.

Публичная версия происходит из публичного GitHub-репозитория с точным commit и subpath. Проверьте объект локально, просмотрите паспорт и публикуйте через CLI. Секреты, приватные пути, кэши и generated output не должны попадать в паспорт.
