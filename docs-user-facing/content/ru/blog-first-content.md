ai_stp — система создания, проверки, хранения, выбора и установки полных конфигураций AI-харнессов. Главный потребитель — кодирующий агент пользователя, который ведёт строгий CLI с одним JSON-конвертом на команду. Сайт владеет аккаунтом и публичным каталогом и показывает результаты оператору. Он не выбирает состав, не собирает пакет и не пишет нативное состояние харнесса.

Дистрибутив на PyPI — `ai-stp-cli`. Исполняемый файл — `ai-stp`. Команда `uv tool install ai-stp` ставит пакет, который этот проект не публикует. Текущая линейка: `0.0.15`.

## Чем продукт является на самом деле

**Харнесс** — CLI-среда, в которой работает кодирующий агент. **Сетап** — полная конфигурация одного харнесса; он принадлежит этому харнессу с момента создания. **Компонент** — часть сетапа одного из восьми видов: `instruction`, `skill`, `mcp`, `hook`, `command`, `agent`, `plugin`, `setting`. Память, правила, параметры и вспомогательные инструменты — содержимое этих видов, а не отдельные виды.

Опубликованная версия закрепляет точные версии компонентов и неизменяема. Доверие — это происхождение, версия и согласие. Совместимость — граф, target и политика — решает до apply. `author_verified` и `component_verified` независимы. Нативные файлы пишет только публичный провайдер харнесса.

Это разделение и есть продукт, а не временная архитектура. Агент может рассуждать о кандидатах. Он не может обойти механический отказ. Сайт может показать карточку. Он не может применить карточку. Карточка каталога — кандидат, а не разрешение: перед выбором смотрят харнесс, точную `X.Y`, линию доверия и две независимые оси подтверждения.

## Кто что пишет

Локальная работа не требует аккаунта. `device init` и паспорт разработчика достаточны, чтобы смотреть, принимать и собирать приватно. Публичный каталог читается анонимно из CLI и с сайта.

Вход через Google или GitHub открывает приватные объекты, синхронизацию, публикацию, устройства и выдачи доступа. Вход не переносит сборку на сайт. Путь остаётся таким:

```text
CLI → паспорта → индекс проекта → поиск → сборка сетапа → проверки
→ план установки → резервная копия → apply через провайдера → статус
```

CLI возвращает один JSON-конверт на команду. Флаги, схемы и `next_actions` берутся из `ai-stp help --agent`, а не из памяти блога. Документация группирует команды, чтобы человеку было куда идти. Если страница и установленный CLI расходятся, побеждает CLI.

ai_stp не вызывает интерфейсы моделей и не требует ключа модели. Единственный исходящий запрос, который CLI делает от своего имени, — необязательный анонимный пинг установки, выключенный, пока оператор не скажет иначе.

## Харнессы этой линейки

Основная поддержка — Claude Code, Codex и Grok Build. Это производственный путь: паспорта, совместимость, сборка сетапа, план провайдера и apply.

Pi, OpenCode, Cursor и Antigravity — бета. Каталог и совместимость есть. Часть пути провайдера, нативной поверхности или UX ещё строже и может просить больше подтверждений. Неизвестный харнесс — `undefined`: годится для чтения, импорта и локальных проверок, отказан для автоматической установки.

Сетап нельзя перенести переименованием. Одни и те же слова означают разные файлы и события в разных CLI. Перенос состава на другой харнесс — явная новая версия, а не смена ярлыка на той же сборке.

## Чем эта линейка не притворяется

Общего командного сетапа нет. Сетап принадлежит аккаунту, а не git-репозиторию. Коллега, который клонирует проект, собирает свой. Выдачи доступа могут отдать приватный объект другому аккаунту; это отношение автор–получатель, а не двое людей, правящих один рабочий сетап.

Внутри продукта нет API модели. Нет рейтингов, нет публичных обсуждений и нет обещания, что опубликованный объект безвреден. Verified означает, что платформа подтвердила идентичность или текущие проверки версии. Это не снимает ответственность за чтение прав `mcp`, `hook` и `plugin`.

## С чего начать

Установите из PyPI командой `uv tool install ai-stp-cli`, затем дайте агенту прочитать `doctor` и машинную справку. Сайт — для каталога, аккаунта, устройств и статуса публикаций. Когда нужно изменить target, вы снова в CLI, а писатель — провайдер. Сборка, проверки и установка остаются на машине оператора; веб их не выполняет.

См. также: [Быстрый старт](https://ai-stp.aiguild.space/ru/docs/quickstart) в справочном центре.
