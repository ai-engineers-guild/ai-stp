Этот журнал описывает текущую линейку `ai-stp-cli`, версия пакета `0.0.15`. Это продуктовый лог для операторов и агентов, а не заметка о web deploy profiles.

Исполняемый файл — `ai-stp`. Дистрибутив на PyPI — `ai-stp-cli`. Каждую команду, которую агент копирует из документации, следует запускать с `--json`.

## Добавлено

CLI — рабочая поверхность. Он обнаруживает нативные компоненты, записывает паспорта, ищет в публичном каталоге без аккаунта, компилирует точный граф сетапа и запрашивает план у провайдера харнесса. Apply, резервная копия, статус и именованный откат идут через этого провайдера. Сам CLI нативные файлы харнесса не пишет.

Локальная идентичность есть: `device init`, паспорта разработчика и устройства, реестр на SQLite и локальное хранилище, адресованное по содержимому. Облачный вход через Google или GitHub открывает приватные ревизии, `sync push` / `sync pull`, публикацию, устройства и выдачи доступа. Локальная работа не требует аккаунта.

Публикация — сначала план, затем подтверждение. Публичная `X.Y` — неизменяемые байты плюс паспорт версии, из публичного репозитория GitHub на точном коммите и подпути. Подписи устройства связывают запись подтверждения. Подтверждение автора и подтверждение компонента хранятся и показываются как независимые оси.

Проверки безопасности выполняются как поэтапный неисполняющий набор, прежде чем публичный компонент считается подтверждённым. Обязательные проверки блокируют публикацию, если они провалились или не могут выполниться. Необязательные сканеры дают предупреждения или неполное покрытие; недоступный движок никогда не считается проходом.

Приватная синхронизация — упорядоченный журнал аккаунта. `sync pull` применяет одну ограниченную страницу с последнего подтверждённого курсора. Листинг каталога — отдельная публичная модель пагинации и может закончиться `null`.

Сайт показывает публичный каталог, профили издателей, аккаунт, устройства, публикации и этот content hub. Человеческая и машинная проекции одних и тех же публичных страниц существуют как равные маршруты. Сайт не собирает и не устанавливает сетап.

## Изменено и закреплено

Точные pin заменили диапазоны. Сетап принадлежит одному харнессу с момента создания. Изменение состава создаёт следующий minor. Новая major-линия — явное решение `--major`, никогда не значение по умолчанию.

Линии доверия — `authoritative`, `experimental` и `local_owner_or_pinned`. Экспериментальные объекты появляются только с явным согласием, в отдельной секции, и никогда не выбираются автоматически. Локально свои или закреплённые объекты от этого не становятся платформенно подтверждёнными.

Запись провайдера связана с digest. Устаревшие планы отклоняются. Прерванный apply восстанавливают чтением статуса, а не угаданным вторым apply.

## Семейства команд этой линейки

В реестре 142 команды. Карта справочного центра их группирует; машинная справка по-прежнему `ai-stp help --agent --json`. Сегодня есть:

- наблюдение: `version`, `doctor`, `help`, `capabilities`;
- идентичность: `device`, `passport`, `auth`, `config`, `consent`, `telemetry`;
- авторинг: `component discover` / `adopt` / паспорт / источник / `version release` / `skill validate` / `publication`;
- каталог: `registry search` / `show` / `version` / `fetch` / `acquire` и порт SX/APM;
- сборка: `select`, `setup compose` / `import` / `update` / `publish`;
- apply: `install plan` / `approve` / `apply` / recover, `provider`, `target`;
- аккаунт: `sync`, `grant`, `owner`, `report`.

Нет `component inspect`, нет `setup show`, нет `ai-stp contact`. Флаги в статьи не копируются: они едут с установленным CLI.

## Какие пределы остаются

Pi, OpenCode, Cursor и Antigravity — бета. Claude Code, Codex и Grok Build — основной путь. `undefined` — ограниченная строка переносимых соглашений, не harness, в который ставят автоматически.

Общего командного рабочего сетапа нет. Внутри ai_stp нет API модели. Нет рейтингов и публичных обсуждений. Нет абсолютного обещания, что опубликованный объект безвреден.

Лайк — не pin. Выдача на major `1` не открывает `2`. Отзыв действует только вперёд: локальные байты на диске получателя могут остаться. Недоступный движок проверки никогда не считается pass.

## Как читать этот журнал

Это не git-история. **Добавлено** — рабочая поверхность на `0.0.15`. **Изменено и закреплено** — контракт, который не ослабнет молча. **Какие пределы остаются** — отказы, а не бэклог, который стоит пережидать.

После установки или обновления `ai-stp-cli` проверьте, что этот журнал описывает бинарник в `PATH`:

```bash
ai-stp version --json
ai-stp doctor --json
ai-stp help --agent --json
```

`cli_version` должен быть `0.0.15`, иначе журнал про другую линейку. Если машинная справка называет флаг, которого нет в статье, следуйте бинарнику. Если статья называет команду, которой нет в реестре — нет `component inspect`, нет `setup show`, нет `ai-stp contact` — статья неверна.

Тип changelog в хабе материалов — этот документ. Смена темы MkDocs или web deploy profile — не новая линейка CLI. Staff URL — не пользовательская поверхность и в этот журнал не входят.
