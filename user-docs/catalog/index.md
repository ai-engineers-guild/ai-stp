# Каталог

Публичный каталог помогает найти сетапы и компоненты по харнессу, тегам,
совместимости, дате обновления и линии доверия. Режим Both сначала показывает
сетапы, затем компоненты; каждая группа сохраняет выбранную сортировку.

## Анонимное чтение

Читать публичный каталог можно без аккаунта. Это нужно для первого знакомства,
локального подбора и работы агента до авторизации.

```bash
ai-stp registry search --json
ai-stp registry show <stable_id> --json
```

## Что смотреть в результате

Перед выбором объекта проверяйте:

- харнесс и поддерживаемую версию;
- точную версию объекта;
- происхождение и commit source;
- `author_verified` и `component_verified`;
- линию доверия;
- ограничения совместимости;
- результаты последней проверки.

`author_verified` и `component_verified` независимы. Подтверждённый автор не
доказывает безопасность конкретной версии.

| Поле | Что оно отвечает | Красный флаг |
| --- | --- | --- |
| Harness | куда можно применить объект | нужного харнесса нет в списке |
| Version | какая неизменяемая версия выбрана | версия не закреплена точно |
| Source | откуда пришёл объект | нет commit/path или происхождение мутное |
| Trust line | почему объект попал в выдачу | `experimental` без осознанного согласия |
| Verification | что подтвердила платформа | verified только автор, но не компонент |
| Compatibility | какие ограничения есть | beta-харнесс без ручной проверки |

=== "Сетап"
    В сетапе важен полный состав: все компоненты, точные версии и один целевой
    харнесс. Любая замена компонента создаёт новую версию сетапа.

=== "Компонент"
    В компоненте важны вид, область действия и то, как он повлияет на target:
    текстом, tool-доступом, hook-событием, командой или настройкой.

??? question "Почему каталог показывает и человекам, и агентам"
    Человек оценивает смысл, доверие и риск. Agent читает те же факты в
    машинной форме и не должен достраивать missing context из памяти.

## Кэш

CLI может показать объект из локального кэша, если сеть недоступна. Такой ответ
должен указывать момент, когда платформа последний раз подтвердила данные.
