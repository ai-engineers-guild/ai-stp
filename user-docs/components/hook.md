# `hook`

`hook` — действие, привязанное к событию харнесса: до запуска команды, после
изменения файла, перед установкой, перед push или в другой поддерживаемый
момент жизненного цикла.

Hook полезен, когда проверка или подготовка должна происходить автоматически.
Он же самый чувствительный вид компонента: ошибка в hook может менять состояние
без прямого внимания пользователя.

## Где hook уместен

| Сценарий | Почему hook |
| --- | --- |
| Проверить паспорт перед публикацией | событие повторяется и должно быть обязательным |
| Запретить применение без backup | guardrail лучше держать рядом с lifecycle |
| Обновить сгенерированный индекс перед docs build | можно сделать воспроизводимо |
| Напомнить агенту прочитать документ | чаще лучше `instruction`, не hook |
| Установить неизвестный пакет | не подходит без отдельного подтверждения |

## Как работает в `ai_stp`

1. Паспорт описывает событие, действие, target и ограничения.
2. Сборщик проверяет, поддерживает ли харнесс такой lifecycle event.
3. Provider показывает план изменения hook-конфигурации.
4. Пользователь подтверждает применение.
5. После применения hook должен быть виден в status и журнале операций.

??? danger "Почему hook требует повышенного внимания"
    Hook может запускаться тогда, когда пользователь думает о другой задаче.
    Поэтому для `hook` особенно важны preview, backup, понятное имя и быстрый
    способ отключения.

## Мини-чеклист перед включением

- событие понятно человеку;
- действие можно объяснить одной фразой;
- есть способ отключить или откатить hook;
- нет секретов в паспорте;
- provider-план не меняет неожиданные файлы;
- beta-харнесс не требует ручного шага, который вы пропустили.
