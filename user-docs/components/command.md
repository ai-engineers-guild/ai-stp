# `command`

`command` — именованный вход в повторяемое действие: slash command, CLI alias,
agent command или другой поддерживаемый shortcut харнесса.

Command отвечает на вопрос: “какую проверяемую операцию можно вызвать по имени?”

## Command, hook или skill?

| Нужно | Выбирайте |
| --- | --- |
| Человек или агент вручную запускает действие | `command` |
| Действие запускается автоматически на событии | `hook` |
| Агенту нужен подробный workflow с правилами | `skill` |
| Нужно только поменять параметр | `setting` |

## Что делает хороший command

| Свойство | Зачем |
| --- | --- |
| Короткое имя | его легко вызвать и найти |
| Явное описание | агент не угадывает назначение |
| Ограниченные аргументы | меньше риск опасного вызова |
| Машинная help-форма | CLI и agent читают одно и то же |
| Проверяемый output | результат можно использовать в следующем шаге |

=== "Для человека"
    Command экономит повторение и снижает когнитивную нагрузку. Вместо длинной
    инструкции пользователь запускает понятный shortcut.

=== "Для агента"
    Command даёт стабильный путь действия. Агент должен читать доступные
    команды из машинной справки, а не придумывать их из памяти.

## Как `ai_stp` применяет command

Сборщик проверяет конфликт имён, совместимость с харнессом и требуемые права.
Provider затем создаёт нативную команду там, где её ожидает конкретный CLI.

!!! tip "MVP-правило"
    Если команда меняет внешний мир, она должна быть понятна в плане установки
    и не обходить общие правила: digest, подтверждение, backup и rollback.
