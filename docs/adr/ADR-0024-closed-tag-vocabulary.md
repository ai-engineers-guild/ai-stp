# ADR-0024: Теги берутся из закрытого словаря

Статус: принято.

## Контекст

Публикуемая версия обязана иметь непустой список тегов: теги участвуют в поиске и структурных фильтрах наравне с видом объекта и совместимостью. Но правило «непустой нормализованный список» не отвечает, откуда берутся значения.

Свободные теги в каталоге, который читает агент, распадаются предсказуемо. Один и тот же смысл получает `python`, `python3`, `py`, `Python`, `питон`; нормализация регистра и дефисов этого не чинит, потому что расходятся не написания, а слова. Фильтр перестаёт быть фильтром: агент не может спросить «покажи всё для Python», не перечислив синонимы, которых он не знает. Дальше появляется теневая работа по слиянию синонимов и модерации мусорных тегов, которой в MVP некому заниматься.

Первичный потребитель здесь — агент, а не человек, и это меняет баланс. Человек прощает разнобой и догадывается по смыслу; агент выбирает по точному совпадению и молча теряет кандидатов.

## Варианты

1. Свободные нормализованные теги. Ничего не стоит на старте, но фильтр становится ненадёжным, а чистка словаря — постоянной ручной работой.
2. Свободные теги плюс отдельные «официальные». Даёт две сущности с одинаковым именем и вопрос, какие из них участвуют в фильтре.
3. Закрытый версионируемый словарь, который ведёт платформа.

## Решение

Принимается вариант 3.

**Теги берутся только из словаря.** Публикация с тегом вне словаря отклоняется типизированной ошибкой, которая называет неизвестное значение и ближайшие допустимые.

**Словарь машиночитаем и доступен.** Он отдаётся и в CLI, и в API, поэтому агент выбирает теги из перечня, а не придумывает их. Каждая запись словаря имеет устойчивый идентификатор, отображаемое имя, необязательное описание и необязательные синонимы для поиска.

**Синонимы работают на чтение, а не на запись.** Поиск по синониму находит объект; сохраняется в паспорте всегда канонический идентификатор тега.

**Словарь версионируется.** Добавление значения совместимо; переименование отображаемого имени не меняет идентификатор; удаление значения запрещено — вместо него запись помечается устаревшей и перестаёт предлагаться при публикации, не ломая уже опубликованные версии.

**Расширение — отдельный процесс.** Новое значение добавляют владельцы платформы. Пока значения нет, автор выбирает ближайшее существующее; отсутствие нужного тега не блокирует публикацию целиком.

**Предел на объект.** Число тегов у одной версии ограничено, чтобы тег оставался фильтром, а не описанием.

## Последствия

- появляется `contracts/tag-vocabulary.md` как владелец формата словаря, нормализации и предела;
- `SPEC-005` и `SPEC-007` требуют принадлежности тега словарю на публикации;
- поиск фильтрует по каноническому идентификатору и находит по синониму;
- CLI и API отдают словарь, а Agent Skill выбирает теги из него;
- холодный старт каталога требует заполнить словарь до первой публикации.

## Условия пересмотра

Решение пересматривается, если ведение словаря станет узким местом публикации — авторы будут регулярно упираться в отсутствие значения, а владельцы не будут успевать его расширять.
