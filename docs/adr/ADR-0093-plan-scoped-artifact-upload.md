# ADR-0093: Plan-scoped upload байт артефакта

Статус: принято.

## Контекст

План публикации уже несёт точный `content_digest`, а публичное чтение версии
умеет отдать байты. Пишущей половины нет: `ObjectLocation` создаётся только в
тестах, confirm не проверяет, что байты лежат в store. Каталог может показать
метаданные без неизменяемого содержимого. `#312` требует один ограниченный
аутентифицированный путь привязки байт к плану до confirm.

Два предложенных пути: загрузка в план или серверный съём с публичного Git на
точном 40-hex commit и подпути. Оба удовлетворяют issue. Делать оба нельзя:
два писателя разойдутся в упаковке и в отказе.

## Варианты

1. Сервер клонирует публичный Git на объявленном commit и упаковывает подпуть.
   Не требует отдельного клиента загрузки, но тянет сеть, git, упаковку и
   поверхность атаки на содержимое репозитория внутрь confirm.
2. Автор загружает уже упакованные байты на план. Сервер сверяет digest и
   размер, проверяет архив на обход и особые файлы и пишет в существующий
   неизменяемый object store. Git остаётся источником паспорта, не байт store.
3. Presigned PUT в RustFS. Клиент обходит API, ключ хранилища перестаёт быть
   непрозрачным, и `REQ-2004` ломается.

## Решение

Принимается вариант 2.

Маршрут - аутентифицированный `PUT` на план, тело `application/octet-stream`.
Digest и размер берутся из плана, не из заголовка клиента. Confirm читает store
и отказывает, если байт нет. Publish создаёт `ObjectLocation` на уже лежащий
content-addressed объект. Повтор идентичных байт идемпотентен. Другой digest
под тем же `X.Y` по-прежнему отказ по `REQ-2606`.

Съём с Git и presigned URL этим решением не открываются.

## Последствия

- появляется один новый маршрут `/v1`; CLI-клиент загрузки - другой трек;
- worker `upload` не является этим маршрутом: запись идёт синхронно в API, чтобы
  confirm видел байты без гонки с очередью;
- лимит размера и разбор zip принадлежат тому же слою, что safety unpack;
- откат к Git-съёму требует нового ADR и отдельной упаковки.

## Условия пересмотра

Решение пересматривается, если измеренный размер артефакта перестаёт умещаться
в синхронный upload, либо если единственный допустимый источник байт - сам Git
без локальной упаковки. Тогда upload сохраняется, а съём вводится отдельным
маршрутом, не вторым писателем того же digest.
