# ADR-0111: Release candidate собирается там, где будет опубликован

Статус: принято. Продолжает `ADR-0109` и `ADR-0110`, уточняет размещение,
выбранное решением, которое принадлежит приватной инфраструктуре и здесь не
публикуется.

## Контекст

`release-candidate.yml` собирал неопубликованный Python candidate и заверял его
через GitHub/Sigstore build provenance. Он жил в приватной копии и был там
недействующим сразу по двум причинам, ни об одной из которых прогон не сообщал.

Job заверения был условным: `github.event.repository.visibility == 'public'`.
Условие стояло не по ошибке — artifact attestation недоступен приватному
репозиторию на текущем плане, — но в приватном репозитории оно ложно всегда.
Пропущенный job не называется заверенным, и комментарий в самом файле говорил
именно это, ожидая момента, когда репозиторий станет публичным.

Второе: оба job адресовали класс флота. Незарегистрированный или необслуживаемый
класс не отказывает, а ждёт вечно, поэтому workflow мог оставаться неисполнимым,
выглядя исправным. Ни одного прогона у него нет.

Третья причина появилась после `ADR-0109`: Trusted Publishing аутентифицируется
OIDC-токеном, который называет репозиторий. Загружать пакет сможет только тот
репозиторий, который его собрал, а публичным будет `ai-stp`.

## Решение

`release-candidate.yml` принадлежит публичному дереву и исполняется на
стандартных раннерах GitHub. Условия по видимости больше нет: там, где он
теперь живёт, заверение доступно, и пропуск перестал быть возможным исходом.

Приватная копия candidate не собирает. Тест требует, чтобы ни один её workflow
не запрашивал `attestations: write`.

Разделение полномочий из `ADR-0048` сохраняется без изменений и по той же
причине: build не получает ни OIDC, ни права заверения, а заверяющий job
скачивает байты и не делает checkout. Одноразовость раннера даёт это по
построению — машина, собравшая candidate, не существует к началу второго job.
Общий образ раннера не является общей машиной.

Загрузки на PyPI в workflow по-прежнему нет. Публикация требует отдельно
защищённого окружения и явного решения человека, поэтому тест отказывает при
появлении `gh-action-pypi-publish`, `password:` или `api-token`.

## Последствия

`#185` получает место, где может произойти: сборка, заверение и — после
отдельного решения — публикация выполняются одним репозиторием, который
OIDC-токен и называет.

Контракт workflow переезжает в `tests/contract/test_release_candidate_workflow.py`
и публикуется, поскольку доказывать его должно то дерево, которое собирает.
Проверки самих байтов candidate остаются на месте.

Класс флота из вопроса уходит: требовался одноразовый раннер, а не конкретный
флот, и размещённый GitHub раннер это свойство несёт по построению.

## Условия пересмотра

Пересмотреть, если идентичность пакета переедет в другой репозиторий или если появится отдельное окружение, которому нужен собственный candidate.
