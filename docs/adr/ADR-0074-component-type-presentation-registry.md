# ADR-0074: Presentation registry видов компонентов

Статус: принято.

## Контекст

Каталог должен позволять мгновенно различать `instruction`, `skill`, `mcp`,
`hook`, `command`, `agent`, `plugin` и `setting`. Эти виды сейчас являются
закрытым contract enum, а простые интерфейсные иконки не являются содержимым
паспортов. Запрос отдельного изображения при рендере каждой строки ухудшил бы
надёжность и не дал бы пользы при закрытом списке.

## Решение

До появления управляемого каталога видов web владеет исчерпывающим presentation
registry. Он сопоставляет каждому contract identifier одну SVG-иконку из общей
системы штрихов и локализованные названия `ru`/`en`. Registry проверяется на
полноту относительно contract enum. Доменная логика, поиск и паспорта не зависят
от него.

Когда список станет управляемым без выпуска клиента, метаданные вида
(`id`, локализованные имена, accessibility label, media revision) переходят в
PostgreSQL. Версионированные бинарные варианты изображения хранятся в
S3-compatible object storage; БД хранит только content-addressed reference,
размеры и MIME. Клиент получает allowlisted manifest, кэширует его по revision и
оставляет встроенный registry как offline/failure fallback.

## Последствия

Текущий UI не делает сетевых запросов за пиктограммами и не показывает emoji или
буквенные заглушки. Добавление нового contract component type требует обновить
registry и обе локали в одном изменении. Будущий перенос не меняет идентификаторы
видов и не делает object storage источником доменной истины.
