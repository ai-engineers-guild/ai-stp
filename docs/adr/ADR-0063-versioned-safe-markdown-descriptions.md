# ADR-0063: Версионированные безопасные Markdown-описания

Статус: принято.

## Контекст

Паспорт уже является единственным описанием точной версии. Plain text безопасен,
но недостаточен для длинного объяснения состава сетапа; произвольный Markdown без
общего parser/render contract создаёт разные результаты в CLI, API и web и
возвращает HTML, image и URL injection.

Номер `ADR-0049`, предложенный в раннем issue, уже канонически принадлежит
HarnessBundle. Новое решение получает следующий свободный номер `ADR-0063`, не
переписывая историю.

## Решение

Поле `description` остаётся единственным содержательным полем и частью exact
version passport. В passport schema v1 оно всегда означает `commonmark_v1`;
безопасная проекция явно возвращает format и renderer version. Так
паспорт не получает второе поле, а исторические content-addressed bytes не
меняются из-за materialized default.

`commonmark_v1` реализуется CommonMark parser с отключённым raw HTML и закрытым
allowlist token types. Вход дополнительно обязан быть NFC/LF, укладываться в
16 KiB и 256 строк и не содержать control characters. Images запрещены целиком.
Ссылки разрешены только абсолютные `https` без credentials и локальные fragments.

Renderer `safe_markdown_v1` строит HTML только из принятого token tree. Внешним
ссылкам добавляется `rel="nofollow noopener noreferrer"`; source HTML не
санитизируется постфактум, а отвергается до render. Отдельная детерминированная
проекция excerpt извлекает текст и inline code, схлопывает whitespace и ограничена
240 Unicode code points.

Положительные, boundary и malicious cases принадлежат одному JSON corpus в
пакете contracts. Python validator и будущий web renderer обязаны читать его как
один источник, а не поддерживать независимые списки примеров.

## Рассмотренные варианты

1. Хранить plain text. Отвергнуто: не удовлетворяет продуктовому описанию сложных
   сетапов.
2. Санитизировать произвольный HTML после render. Отвергнуто: parser differentials
   и изменения sanitizer создают скрытую вторую семантику.
3. Хранить Markdown и HTML одновременно. Отвергнуто: две изменяемые копии расходятся
   и меняют digest независимо.
4. Загружать remote images через proxy. Отложено: это отдельная media/security
   система и не относится к описанию версии.

## Совместимость

Passport schema v1 всегда проходит полную `commonmark_v1` validation. Неизвестный
format или renderer закрывается отказом. Любое несовместимое изменение grammar,
лимитов, HTML или excerpt получает новую версию, сохраняя старый renderer для
исторических паспортов.

## Последствия

Описание становится выразительным и одинаково проверяемым для человека и агента,
но каждый consumer должен реализовать точный corpus. Remote images и raw HTML
невозможны даже для доверенного автора. Исправление опубликованного текста требует
новой версии, как любое другое изменение паспорта.

## Условия пересмотра

Решение пересматривается при необходимости media attachments, локализованных
описаний или нового CommonMark profile; ни один из этих случаев не добавляет
mutable object-level description автоматически.
