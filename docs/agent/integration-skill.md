# Integration Skill

The canonical Skill contains the procedure for working with the CLI, but does not copy every schema.

It starts with `ai-stp doctor --json`, obtains the command list from `ai-stp help --agent --json`, and invokes only what machine help returns. The Skill itself contains no command list: that list lives in the CLI registry, and a copy would diverge from the implementation on the first change. The Skill then identifies the current harness and project, reads passports, inspects unknown required fields, displays composition, conflict, and conversion reports, applies the remaining stops in `references/decisions.md`, does not remove its own control layer, and returns a recovery command after a partial failure.

The only flags named directly by the Skill belong to the two commands it uses to obtain machine help: help cannot be read from help that has not yet been obtained. Everything else comes from machine help, and a contract check enforces this.

The Skill interprets the `mutability` effect and the machine `confirmation` method separately:
`none` does not mean consent to write, `explicit_flag` requires a fresh decision, and
`plan_digest` binds application to the immutable plan that was shown. A stale
plan is rebuilt and confirmed again; `next_actions` remains advice rather than
authority for the next effect.

The Skill is projected onto the native surfaces of every supported harness.
Projections are generated by `just back-gen` and checked by `just back-static`.
Each projection is the procedure plus harness metadata and a short native-surface
note (`ADR-0149`). It must not point at a repository path. Flags stay in machine
help; command paths may be named.

The canon, its `references/` playbooks, the Russian locale, and every harness
projection ship inside the package. `skill install` writes that package to a
named destination. Without this, a user who installed the wheel would receive an
executable but no procedure.

Installation uses an explicit destination rather than discovery. Where a harness looks for a native Skill is a fact about that harness and differs across the five; inventing five paths would present guesses as support. Discovery will arrive with the harness detectors under `SPEC-014`; until then, the caller—a person, agent, or website installer—specifies the path.

Nothing is overwritten silently. Installation places an ownership record beside the Skill; removal takes only what that record confirms, while a Skill written by someone else or changed after installation remains in place and is named in the response. The local registry and user-configured state are not part of the control layer and are never touched.
