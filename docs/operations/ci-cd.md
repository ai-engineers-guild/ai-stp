# CI и развёртывание

Этот репозиторий сам проверяет себя и сам разворачивает продакшн. Ничего из
описанного ниже не требует доступа: workflow, продвигаемый ref и развёрнутая
identity открыты, поэтому утверждение «развёрнут именно этот коммит» может
проверить любой, а не только тот, у кого есть права.

## Гейт

`check.yml` выполняется на стандартных раннерах GitHub при push в `main`, на
каждый pull request и по ручному запросу. Job независимы и идут параллельно:

| Job | Что доказывает |
| --- | --- |
| `docs` | документация, спецификации, контрактный линт и ссылки |
| `package` | статика, сборка колёс и обратная проверка установки |
| `tests` | набор тестов с порогом покрытия против реальной базы |
| `web` | сборка, типы, unit и e2e веб-приложения |
| `cli (ubuntu / macos / windows)` | поверхность, которая обязана вести себя одинаково на трёх ОС |

Матрица из трёх ОС — не формальность. Она нашла два настоящих дефекта, которых
линуксовый прогон увидеть не мог: падение машинного вывода на кодовой странице,
не умеющей закодировать UTF-8, и обращение к системному хранилищу ключей на
headless-машине, которое не возвращалось.

`codeql.yml` анализирует Python, JavaScript/TypeScript и сами Actions.

Ручной запуск отвечает на вопрос «зелёное ли дерево» и ничего не выкатывает:
развёртывание принимает только push.

## Развёртывание

Развёртывания внутри гейта нет. Оно живёт отдельным workflow и разделено на два
шага, у которых разные права и разные последствия.

`promote` после зелёного `check` на `main` без force продвигает
`refs/heads/deploy/prod` на точный проверенный SHA. Это единственная запись,
которую делает CI, и единственное право, которое ему нужно.

Целевой хост не является раннером и не принимает входящих соединений от CI.
Минутный systemd timer забирает этот один ref исходящим соединением, извлекает
коммит, переносит дерево, сохраняя `.env*` и состояние хоста, и запускает
локальное развёртывание (`ADR-0103`). Забор анонимный по HTTPS: репозиторий
публичный, поэтому на хосте нет ключа развёртывания, который можно потерять или
который нужно ротировать (`ADR-0109`).

`verify-public` затем доказывает результат снаружи — с раннера, а не с хоста:
проверка, выполняемая там же, где работает сервис, не отличает «поднято» от
«поднято для меня». Она ждёт, пока цель развернёт продвинутый коммит, и
сравнивает identity, здоровье и имя среды.

Развёртывание асинхронно относительно `promote`. Авторитетный ответ на вопрос
«что развёрнуто» — `GET /v1/system/version`; `git_commit` в нём разрешается в
коммит этого репозитория.

## Секреты

Ни один workflow не читает секрета развёртывания, потому что такого секрета
нет. Настройки приложения живут в файле окружения на самом хосте, который не
переносится и который не читает и не пишет ни один workflow. Всё, что нужно
проверкам, приходит из GitHub secrets и никогда не попадает в дерево.
