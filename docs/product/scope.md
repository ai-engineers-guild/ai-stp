# Границы MVP

## Стадия

Состояние работ принадлежит `docs/engineering/implementation-roadmap.md` и здесь не повторяется. Этот документ отвечает на другой вопрос — что входит в MVP, а что нет. Копия стадии в двух местах уже разошлась однажды и разойдётся снова: она устаревает при каждом продвижении, а заметить это некому.

Согласованы и приняты продуктовый контракт, доменная модель, паспорта и версии, протокол провайдеров, модель доверия, синхронизация, контракты CLI и API, runbooks, quality gates и Agent Skill. Открытых противоречий между спецификациями нет.

Реализация ведётся в порядке `docs/engineering/implementation-roadmap.md` и не опережает его ограничения: облачная публикация не начинается до неизменяемых локальных схем, а серверный контур параллелится только после заморозки схем локального состояния и API.

## Харнессы

| Статус | Харнессы |
|---|---|
| Основная поддержка | Claude Code, Codex, Grok Build |
| Бета | Pi, OpenCode, Cursor, Antigravity |
| Неизвестный | `undefined` без автоматической установки |

Первый выпуск блокируют только основная поддержка и полнота продуктовых требований. Бета-линии продвигаются независимо.

## Обязательно

- установка CLI через команду с сайта и `uv`;
- локальный реестр на SQLite;
- PostgreSQL и RustFS/S3 в server mode;
- Google/GitHub OAuth;
- устройства с ID и ключом;
- паспорта разработчика, устройства, проекта, сетапа и компонента;
- индекс ограниченных безопасных текстовых файлов проекта;
- ограниченный символьный индекс для Python, TypeScript/JavaScript, Rust, Go и Dart/Flutter;
- полный набор инструментов `mvp-full` при первичной настройке;
- анонимное чтение публичного каталога;
- приватные drafts и cloud sync после auth;
- поиск по тегам и структурным фильтрам;
- три линии доверия с явным согласием на непроверенное;
- произвольная композиция компонентов;
- профиль выполнения `full-auto`;
- повышенное число подтверждений в configuration workflow;
- точные версии `X.Y`;
- резервная копия, plan, apply, launch, status и restore;
- импорт существующей нативной конфигурации в личный сетап;
- ежедневный цикл `status`, `rescan`, `search`, `diff`, `update` и `rollback`;
- права по account ID и приглашения по подтверждённой почте;
- веб для учётной записи и публичного каталога;
- жалоба на объект из веба и CLI в единый закрытый случай модерации;
- удаление CLI с сохранением данных и отдельный purge;
- Agent Skill на русском и английском с нативной проекцией для семи харнессов.

## Не входит

- реальные платежи и выплаты;
- рейтинги и социальная лента;
- браузерный редактор сетапов;
- Windows runtime support;
- постоянный desktop daemon;
- автоматические обновления и каналы выпуска;
- оформление чужих open-source компонентов силами платформы для наполнения каталога;
- свободные теги вне словаря;
- организация/команда/enterprise landscape;
- общий сетап проекта для нескольких разработчиков и его ревью;
- рейтинги, публичные обсуждения и автоматические публичные issue из жалоб;
- собственный вызов интерфейса модели из `ai_stp`;
- векторные представления, граф вызовов и полный семантический граф;
- APM или SX как обязательное ядро;
- автоматическая установка объектов непроверенных авторов;
- абсолютное обещание отсутствия уязвимостей.
