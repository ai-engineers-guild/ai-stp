# Материал для второго ревью CLI-трека спринта 1

Статус: заменён. Второе ревью CLI-трека спринта 1 выполнено. Документ сохранён как исторический материал и действующим требованием не является.

Продвижение принимается только после второго ревью по `docs/engineering/git-workflow.md`. Этот документ существует, чтобы второе ревью занималось решениями, а не археологией: он называет, что именно требует чужого взгляда, где это лежит и как проверить руками.

Автор трека — `rldyourmnd`. Второй ревьюер — `letya999`.

## Что проверить в первую очередь

Три вещи фиксируют поведение **платформенного** трека, и ошибка в них дороже всего, потому что менять их придётся согласованной миграцией по правилу #70.

| Что | Где | Почему это к платформе |
|---|---|---|
| Набор проверок готовности | `schemas/v1/openapi.json`, маршрут `GET /v1/health/ready` | Контракт фиксирует, что именно сервер обязан проверять и как отвечать |
| Форма аккаунта и связанных identity | `packages/contracts/src/ai_stp_contracts/identity.py` | Определяет, что сервер отдаёт на `GET /v1/account` |
| Семантика отзыва устройства | там же, `DeviceRevokeRequest`/`Response` | Отзыв опережающий: сводка помечается, локальные данные живут |

Каждая уже закреплена фикстурами корпуса. Несогласие с решением — это изменение контракта, а не правка кода.

## Отступления от текста задач

Каждое сознательно, каждое с записанным основанием. Ревью должно проверить основание, а не факт отступления.

| Отступление | Задача | Основание |
|---|---|---|
| Click вместо Typer | #72 | `ADR-0057`: посылка `ADR-0013` исчезла; измерена несовместимость вендоренного Click-шима Typer с установленным Click |
| Нет команды записи конфигурации | #73 | `cli-config.md` делает третий ярус приоритета переопределением на вызов; писателя не требует ни один `REQ-*` |
| Стандартный `sqlite3` вместо Alembic | #74 | `ADR-0059`: 510 мс импорта и 14 МБ против 2 мс |
| Локальный владелец до входа | #74 | `ADR-0060`: автономный контур обязан создавать паспорта раньше аккаунта; #75 переносит владение ревизией |
| Вход двумя командами | #75 | CLI не подвешивает ничего в ожидании человека; две фазы отвечают разными payload при одном `result_schema` |
| Три группы команд отсутствуют | #72 | `passport`, `auth`, `registry` появились в своих задачах; объявленная нерабочая команда попала бы в машинную справку |

## Изменения общих путей

По правилу «shared schemas/foundation меняются только через #71 или отдельно отревьюенное интеграционное исправление» их четыре:

- `apps/*` заведён в гейт через корневой `pyproject.toml`;
- граница агент↔CLI опубликована в `packages/contracts` и `schemas/v1` (схемы `cli-*`);
- `HARNESS_IDS` выведен из `HarnessId` вместо повторения значений;
- три случая корпуса несли заглушку `passport_digest`, не описывающую их паспорт — исправлено, инвариант добавлен.

## Как проверить руками

```bash
just check
uv build --all-packages --out-dir /tmp/pack && uv venv /tmp/env
VIRTUAL_ENV=/tmp/env uv pip install --find-links /tmp/pack ai-stp-cli
/tmp/env/bin/ai-stp doctor --json
/tmp/env/bin/ai-stp help --agent --json
```

Полный локальный контур без сети и аккаунта: `device init`, `passport developer init`, `passport developer show`, `passport device refresh`, `passport device show`, `device show`, `config show`, `auth status`. Облачные команды без платформы обязаны отвечать типизированным кодом, а не падать.

## Что ревью не найдёт в коде

Два класса дефектов уже были найдены и закрыты гейтами, а не правками. Ревью стоит проверить сами гейты, а не искать экземпляры:

- **достижимость** — пять предохранителей были написаны, покрыты тестами и не подключены ни к чему; покрытие такое не видит, потому что функция, до которой доходит только её собственный тест, покрыта на 100% и мертва (`tests/contract/test_reachability.py`);
- **висячие имена документов** — имя в обратных кавычках, за которым нет файла, дважды пережило ревью, потому что это не ссылка Markdown (правило `LN002` в `docs_scripts/docs_lint.py`).
