# Git workflow

## Одна линия

`main` — единственная линия репозитория. Она одновременно интеграционная и
выпускная. Отдельной `dev`, общей
agent-ветки или ручной очереди продвижения нет. Изменение существует в продукте
только после попадания в `main` и зелёной проверки exact SHA.

Текущий authenticated участник или агент вправе сделать проверенный атомарный
commit и push прямо в `main`, когда это входит в поручение завершить,
синхронизировать или выпустить работу. PR применяется, когда нужен независимый
review, обсуждение публичного контракта или изоляция параллельной работы; он не
служит обязательным подтверждением разрешения владельца.

## Синхронизация участников

Перед началом и перед commit:

1. выполнить `git fetch --prune` и сравнить `HEAD...origin/main`;
2. сохранить все чужие/параллельные изменения и определить их владельца;
3. если `origin/main` ушёл вперёд, интегрировать его без потери локального diff;
4. после интеграции повторить затронутые проверки.

Изменения коллеги не ждут отдельного «приёма»: свежий `main` является исходной
точкой следующей работы. Нельзя использовать reset/checkout для очистки чужого
diff. Исправление ошибки идёт следующим commit, а не переписыванием общей
истории.

## Herdr

Herdr panes могут смотреть один checkout. `herdr agent list` показывает active
cwd, а `herdr agent prompt` используется для обмена точными путями и границами.
Перед генератором или commit каждая сессия повторно проверяет общий `git status`.
Параллельные зоны выбираются по файлам/слоям; факт из другого репозитория
передаётся сообщением и перепроверяется у потребителя.

## Public и private

Каноническая разработка идёт в публичном `ai-engineers-guild/ai-stp`. Private
underscore tree импортирует точные public bytes штатной командой и подтверждает:

```text
just public-sync <public-checkout>
just public-sync-verify <public-checkout>
```

`disagreements: 0` засчитывается только из правильного private cwd и при
указанном втором checkout. Private-only deployment history не публикуется.
Изменение публичной документации, сделанное при private-аудите, возвращается в
public tree после сведения параллельной public работы; оно не остаётся второй
нормой в underscore copy.

## Коммиты

- Один commit имеет одну причину: import/sync, поведение, docs или generation.
- Индексируются явно названные пути; общая команда добавления всего дерева не
  используется при параллельной работе.
- Generated source и output фиксируются вместе.
- Author/committer берутся только из global Git config; локальные identity
  override, `--author` и фиктивные trailers запрещены.
- Проверки выполняются после последней смысловой правки; результат другого SHA
  не переносится.

Commit message и итоговый отчёт называют эффект, выполненные проверки,
неисполненное evidence и способ возврата. Вопрос перед обратимым commit/push не
заменяет ни одного из этих доказательств.

## PR, теги и выпуск

PR при использовании содержит границы, contracts/specs, base/head SHA, migration,
проверки, пропущенное evidence и rollback. Изменение после review требует нового exact
CI, но не обязательного человеческого клика, если task authority уже существует.

Тег/PyPI/deploy — отдельные операции с собственным exact plan/evidence, а не
автоматическое следствие merge. Поручение «закончить и выпустить» разрешает
агенту выполнить их последовательно через текущие authenticated accounts и
protected environments. Новое решение нужно только для классов
необратимости/расширения доступа из `ADR-0118`.

## Межрепозиторная работа

`ai_stp` и setup-systems имеют отдельные mutation boundaries. Изменение
реализации provider, его выпуск, vendor kit и продвижение consumer pin не
смешиваются в один Git commit. Совместный порядок:

```text
producer contract + tests
→ producer release
→ consumer pin/enforcement
→ exact cross-repository evidence
```

Окно совместимости и временный `not_verified` называются прямо. Документ или
review старого SHA не замещает измерение текущего producer/consumer pair.
