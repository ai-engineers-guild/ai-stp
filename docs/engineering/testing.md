# Тестирование

## Уровни

| Уровень | Назначение |
|---|---|
| Unit | Чистые правила и преобразования без I/O, часов и сети. |
| Property | Digest, merge, version, graph и state-machine invariants. |
| Integration | SQLite/PostgreSQL, filesystem, object storage, OAuth adapters. |
| API | ASGI-уровень через httpx AsyncClient против фабрики приложения: конверт, ошибки, health. |
| Scenario | Сквозные потоки между слайсами платформы в одном процессе. |
| Contract | CLI JSON, API, schemas, provider protocol, паритет OpenAPI против фикстур `#71`. |
| E2E | Главные пользовательские пути. |
| Security | Paths, authz, tenant isolation, archive and subprocess boundaries. |
| Fault | Crash, timeout, stale plan, partial apply, retry. |
| Phase | Отбор доказательств по фазе дорожной карты через маркер фазы. |
| Golden | Passports, plans, bundles, conversion reports. |

## Обязательные сценарии

- паспорт сохраняет origin при переходе в confirmed;
- изменение паспорта не меняет публичный профиль;
- duplicate `X.Y` с новым digest отклоняется;
- ссылка на версию сетапа не содержит вариант, а перечисление видов компонента не содержит `marketplace`;
- unverified object попадает в выдачу только по явному согласию и не входит в automatic setup;
- два устройства хранят разные окружения без изменения и конфликта паспорта разработчика;
- отмена сеанса рекомендации не создаёт версию, а подтверждение атомарно создаёт ровно одну;
- области согласия `publisher` и `object_major` различаются, а расширение полномочий требует нового решения;
- право на линию `X` не открывает `X+1`, форк не меняет оригинал, отзыв сохраняет локальные данные;
- жалоба не содержит секретов и путей и не меняет состояние версии без действия модератора;
- истечение обязательного доказательства блокирует новые установки, не отключая установленную цель;
- каждый вид компонента и класс транспорта MCP покрыт политикой проверок;
- arbitrary graph обнаруживает все классы конфликтов;
- приглашение не даёт доступа до подтверждения адреса входом;
- индекс видит смешанное дерево расширений и исключает секреты, кэш и генерируемые результаты;
- автономный путь работает после отключения сети;
- stale plan не применяется;
- backup/restore сохраняют unmanaged state;
- revoked device не синхронизируется;
- three-way merge не теряет изменения;
- partial operation не объявляется success;
- old/new schema/API compatibility;
- Linux x86_64 E2E для всех пяти release lines;
- переносимые Windows fixtures для `.exe`, `.cmd`, npm/Scoop metadata и Codex
  Desktop `WindowsApps`, с обязательным `version_source` и диагностикой;
- ручной macOS portability evidence до будущего расширения support matrix.

## Разделение платформы и CLI

Тесты серверной платформы отделены от тестов CLI подкаталогами `tests/<уровень>/platform/` и `tests/<уровень>/cli/` и маркерами `platform` и `cli`. Conftest одной области не импортируется в другую, поэтому фикстуры платформы и CLI не смешиваются. Иерархия conftest такова: корневой регистрирует маркеры и детерминированные помощники, платформенный даёт фабрику приложения, асинхронный клиент и фикстуры базы и очереди, а границы уровней не пересекаются.

Изоляция базы остаётся на тест, но её стоимость — нет: цепочка Alembic применяется один раз на процесс в мигрированный template (`pg_migrated_template`), и каждый тест получает собственную базу клоном `CREATE DATABASE ... TEMPLATE`. Тест, проверяющий сами миграции, работает с пустой базой через `isolated_database_url` и применяет их сам — он единственный, кто платит полную цену повторно. Трассировка покрытия идёт через `sysmon` и несовместима с `concurrency=greenlet`. Решение и замеры стоимости — `docs/adr/ADR-0117-the-test-run-does-not-repeat-expensive-work.md`. Публичный гейт гоняет серверный набор только на Linux, разрезанным на шарды, а CLI и веб-тесты — на трёх ОС (`docs/adr/ADR-0116-the-gate-spends-runners-on-os-and-shards.md`).

Потребность в PostgreSQL не поддерживается списком вручную: корневой conftest ставит маркер `pg` по fixture-замыканию теста, поэтому `-m "not pg"` выбирает набор, которому база не нужна, ровно настолько, насколько она нужна на самом деле.

## Правила тестов

- Иммутабельные ненаивные тесты без хардкода: ожидаемые значения выводятся из констант и реестров `ai_stp_foundation` и из билдеров, а не копируются литералами; коды ошибок берутся из реестра, а не пишутся строкой.
- Детерминизм и отсутствие флаки: без `sleep`, только ожидание условий и событий; замороженные часы; посеянная случайность; без реальной сети; изоляция базы на тест через транзакцию с откатом; без общего изменяемого глобального состояния.
- Если большая suite падает или зависает, применить описанный одноразовый fallback — одна collection, 20 стабильных ordered shards, одинаковая среда, no coverage только для локализации, журнал outcome/duration, затем узкое воспроизведение и root-cause fix; sleep, blind retry и постоянное шардирование без доказательства запрещены.
- Реальное поведение и минимум моков: мокается только внешний сервис, но никогда не проверяемая единица.
- Имена и группировка: имя вида `test_<субъект>_<условие>_<ожидание>`, группировка по поведению, а не по методу.
- Осмысленные проверки наблюдаемого поведения и инвариантов, а не случайной структуры.
- Каждая строка приёмки `REQ-*` имеет хотя бы один исполнимый тест, а контрактные тесты привязаны к фикстурам `#71`.

Тест должен называть поломку, которая сделает его красным.
