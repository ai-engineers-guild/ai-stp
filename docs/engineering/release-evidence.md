# Доказательства выпуска

## Общая запись

Каждый выпуск фиксирует репозиторий, ref и SHA, версию, хэш и происхождение артефакта, версии схем, точные команды и результаты, пропущенные проверки, итоговый diff, состояние рабочего дерева, миграцию, возврат и известные ограничения.

Старый запуск CI на другом SHA не является доказательством. Пропущенная линия получает `not_verified`, а не успех.

## CLI

Требуются чистая установка опубликованной командой, Python 3.12 и 3.14 на Linux
x86_64, автономный путь, удаление и повторная установка, эталонный JSON и проверка
отсутствия секретов. macOS по `ADR-0062` не входит в текущую support matrix.

Python candidate дополнительно несёт согласованные версии пяти публичных пакетов,
побайтово повторённые wheel/sdist, package metadata и LICENSE, детерминированный
CycloneDX SBOM, `release-manifest.json`, `SHA256SUMS` и provenance exact SHA. Dirty
candidate, пропущенная attestation или существование workflow без успешного запуска
получают `not_verified`.

Доказательство установки дополнительно фиксирует происхождение по PEP 610 всех пяти
внутренних колёс, переданных прямыми источниками. Установка только колеса CLI с
`--find-links` недостаточна: совпадающие внутренние версии могли разрешиться через
публичный индекс. Проверка исполняет машинные команды вне исходного дерева и
подтверждает удаление программы. Каждая строка Python matrix обязана использовать
job-local `UV_PROJECT_ENVIRONMENT` и сверить фактическую версию Python из ответа
установленного CLI; один persistent `.venv` не является доказательством двух версий.

## Платформа

Требуются миграции PostgreSQL, изоляция пользователей, полномочия объектов, работа RustFS, идемпотентность заданий, смешанные версии API, аудит администратора, резервная копия и восстановление.

## Провайдер

Требуются точный публичный источник, артефакт и манифест выпуска, политика доверия, подпись, хэш, защита от отката, публичные проверки, закрытое подтверждение соответствия, вредоносные пакеты, план без изменений, применение, запуск, состояние и восстановление.

Linux x86_64 обязателен для всех пяти провайдеров. Claude Code и Codex блокируют
основной выпуск, три beta-линии проходят тот же безопасный lifecycle, но не
усиливают свой support label. Неисполненная платформа не называется поддерживаемой;
macOS получает `not_verified` и текущий выпуск не блокирует.

## Первый публичный каталог

Состав каталога запуска — выпускной барьер по `ADR-0034`, а не инвариант схем. Первый публичный выпуск требует инвентаризации:

- по одному базовому сетапу для Claude Code, Codex, Pi, OpenCode и Grok Build;
- ролевые семейства сняты из барьера поправкой к `ADR-0034` от 2026-08-28: их источник заархивирован, живого репозитория для пересборки нет, а провенанс внутри адресуемого содержимым паспорта правкой не чинится;
- переиспользуемые первопартийные компоненты, достаточные для сборки этих сетапов;
- каждый объект запуска опубликован из подтверждённого пространства имён AI Engineers Guild с полным паспортом, происхождением, актуальными обязательными доказательствами и доказательствами совместимости и установки;
- содержимое объектов каталога запуска — инструкции, описания и компоненты — ведётся на английском по `ADR-0035`;
- каждая точная ссылка каталога запуска разрешается, и ни один объект не имеет истёкших или отсутствующих обязательных доказательств.

Ролевые семейства владельцы гильдии делят между собой, и взаимное ревью каждого объекта запуска обязательно. Базовые сетапы бета-харнессов минимальны: определение, установка и честная пометка уровня ниже основной поддержки; глубина Pi, OpenCode и Grok Build выпуск не блокирует. Конкретное содержимое объектов создаётся контентным этапом против реальных харнессов и здесь не фиксируется.

## Линии выпуска

Первый выпуск MVP блокируют полнота продуктовых требований ядра, локального контура, сервера и веба, полное сквозное доказательство Claude Code и Codex по заявленной матрице и укомплектованный каталог запуска из раздела выше.

Линии Pi, OpenCode и Grok Build продвигаются независимо и первый выпуск не блокируют. Неполнота бета-доказательств не является основанием ни задержать выпуск, ни объявить бета-линию поддержанной: линия без записанного запуска получает `not_verified`.

## Блокирующие условия

Выпуск блокируется при нерешённой находке первого приоритета, устаревшей закреплённой версии провайдера, отсутствующем исходном артефакте, несовпадении схемы и документации, уязвимости зависимости выше утверждённого порога или отсутствии инструкции восстановления.
