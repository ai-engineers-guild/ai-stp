# Quality gates

## Документационное основание

- frontmatter, ссылки и anchors;
- отсутствие незаполненных placeholders;
- полнота и паритет `index.md`;
- Markdown и YAML;
- реальный Mermaid render;
- структура и трассируемость active specs;
- семантические регрессии: отменённые термины, паритет веток, покрытие политики проверок, отслеживаемое состояние сессии и возвраты закрытых решений видения — публикуемый обязательный `not_run`, бессрочное согласие, вечный потолок харнессов, урезанный веб, зашитые счётчики, факты окружения в паспорте разработчика, исключённый канал жалоб, потерянные канонические контракты решений;
- unit tests документационных валидаторов;
- строгая сборка MkDocs.

Семантический проход отличается от разметочного: он ловит возврат уже отменённого решения другим словом, что не ломает ни ссылки, ни frontmatter. История в `docs/adr/` из него исключена намеренно — заменённое решение обязано уметь описать, что оно заменило.

## Код после bootstrap

- Ruff format/check;
- Pyright strict;
- architecture imports;
- secret scan;
- dependency review, включая отсутствие клиента интерфейса модели;
- unit/property;
- integration;
- contract/schema/golden;
- security;
- package/install;
- E2E.

С фазы 1 в `just check` уже включены: Ruff format/check и Pyright одним прогоном `back-static` (strict для `packages/`, `apps/` и `tests/`, basic для `docs_scripts/` до полной типизации валидаторов), pytest с unit-, property-, contract- и golden-проверками (`back-test`), порог покрытия по `packages/` и `apps/` (см. ниже), байтовый паритет `schemas/v1` с моделями и актуальность проекций Skill (оба внутри `back-static`) и установка собранного колеса в пустое окружение (`back-regress`).

### Условия редистрибуции шрифтов

`just fonts-licence` читает `name`-таблицу каждого отслеживаемого шрифта и
докладывает, что файл говорит о себе сам: записи `0`, `7`, `13` и `14` несут
копирайт, товарный знак, лицензию и её адрес.

Проверка существует потому, что шрифт — единственный бинарник, который
репозиторий обычно носит и который способен запретить собственное присутствие,
и потому что найденное руками один раз больше не перепроверяется. Ручной осмотр
нашёл вдвое меньше файлов, чем `git ls-files`, потому что смотрел одну папку.

Она же нашла собственный пробел. Subsetting шрифта для веба вырезает текст
лицензии из записи `13`, оставляя её адрес в записи `14`, — то есть для файлов,
которые сайт действительно отдаёт, URL часто единственное оставшееся заявление
об условиях. Пока проверка его не читала, каждая OFL-гарнитура выглядела
`restricted` по строке «all rights reserved» из копирайта.

Наблюдаемое состояние: шестнадцать отслеживаемых файлов. Восемь — гарнитуры,
которые отдаёт сайт: IBM Plex Sans и IBM Plex Mono под OFL, `permissive`. Восемь
остальных — две копии исходных гарнитур в `docs/references/prototypes/`, которые
сайт не отдаёт, но репозиторий по-прежнему распространяет. Они остаются
открытым решением владельца: удаление ломает рендер прототипов, а сохранение
несовместимо с публичностью и AGPL.

Замена гарнитур закрыла и вторую проблему: заменённые не несли кириллицу, и
русский интерфейс молча падал на Arial. IBM Plex — одна суперсемья, поэтому
отношение sans/mono, на которое опирается бренд, пережило замену.

Рецепт намеренно вне `just check` и по умолчанию возвращает `0`. Остаётся ли
restricted-шрифт в репозитории — лицензионное решение владельца со своей ценой,
и падающий сегодня гейт принял бы это решение за него. `--strict` возвращает
ненулевой код и предназначен release-гейту после того, как решение принято.
`fonttools` подаётся через `uv run --with` и в lockfile проекта не входит.

### Порог покрытия сравнивается с округлённым значением

`--cov-fail-under=90` задан в `pyproject.toml`, `precision = 2` — там же, и `back-test`
дополнительно перечитывает записанные данные отдельным вызовом
`coverage report --precision=2 --fail-under`. Ядро трассировки — `sysmon`
(`docs/adr/ADR-0117-the-test-run-does-not-repeat-expensive-work.md`);
`concurrency` не содержит `greenlet`, иначе coverage молча откатывается на
`ctrace`.

Порог 90% — решение владельца проекта. Числа `95` и `94.55` ниже сохранены: они
воспроизводят инцидент, а не текущую настройку.

Причина такой конструкции механическая и проверена. `coverage` решает вопрос так:

```python
return round(total, precision) < fail_under
```

При `precision = 0`, которое было умолчанием, порог `95` реально пропускал `94.55`
и `94.88`: округление даёт `95`, и `95 < 95` ложно. При этом `pytest-cov` печатает
свою строку отказа по неокруглённому значению, поэтому прогон одновременно сообщал
`FAIL Required test coverage of 95% not reached. Total coverage: 94.55%` и завершался
успехом на уровне step, job и run. Зелёная галка означала не пройденный порог, а
попадание в полосу шириной полпроцента прямо под ним.

Воспроизведено на `letya999@6a41c28`: `just check` возвращает `0`, печатая отказ при
`94.88%`. Тот же прогон без `AI_STP_TEST_DB_URL` даёт `87.38%` и корректно возвращает
`1` — разница была не в наборе тестов, а в попадании в полосу.

`precision = 2` сужает полосу с половины процента до `0.005`. Полностью убрать её
нельзя: сравнение округлённое по устройству. Поэтому второй вызов остаётся —
он читает записанные данные и отказывает сам, с той же явной точностью. Убирать
любую из двух половин нельзя: одна задаёт точность сравнения, вторая не позволяет
гейту зависеть только от кода возврата `pytest`.

Обязательный `back-resource` повышает до ошибки и прямой `ResourceWarning`, и
`PytestUnraisableExceptionWarning`: финализатор SQLite в Python 3.13+ может завернуть
первый во второй, поэтому одного фильтра недостаточно. Гейт запускает только
контрактную CLI lifecycle-проверку, многократно вызывает читающие команды в одном
процессе, принудительно запускает GC и требует неизменного числа открытых
дескрипторов. Это защищает длительный agent process, а не только обычный
короткоживущий CLI process. Общий `back-test` отдельно сохраняет
`PytestUnraisableExceptionWarning` как ошибку для всего Python workspace.

Platform-тесты с PostgreSQL (`tests/api/platform`, `tests/integration/platform`) читают `AI_STP_TEST_DB_URL`. Без него они skip; coverage падает ниже порога. Локальный DSN и контейнер — в `QUICKSTART.md`; CI поднимает `postgres:16` и выставляет тот же URL.

Изоляция тестов задана репозиторием, а не памятью автора теста. `tests/conftest.py` перенаправляет каталоги XDG во временное дерево и подменяет обнаружение хранилища секретов, поэтому ни один тест не читает конфигурацию, идентичность или ключи разработчика: чтобы дойти до настоящего keyring, тесту пришлось бы постараться. Отсюда следует правило кода: обнаружение вызывается через модуль, а не через имя, импортированное при загрузке — имя подменить уже нельзя, и однажды из-за этого `doctor` в тестах ходил в настоящее хранилище.

`back-regress` ставит колёса, собранные `back-build` в `dist/`, и выполняет два шага подряд; второй видит то, чего не видит первый. Первый шаг существует потому, что рабочее окружение содержит зависимости групп `docs` и `dev`: необъявленная зависимость пакета в нём не видна и проявляется только у того, кто установил колесо. Так уже прошёл незамеченным импорт `yaml` в `apps/cli`. Шаг собирает все пакеты, ставит `ai-stp-cli` в чистый venv, запускает объявленные команды и проверяет, что в установленном замыкании нет клиента интерфейса модели (SPEC-011 REQ-1118). Второй шаг ставит CLI ровно той командой, которую обещает лендинг, и снимает его обратно: он проверяет точку входа на PATH, работу вне исходного дерева и то, что удаление снимает только файлы программы. Локальные данные при удалении остаются — их очистка является отдельным явным действием пользователя. Для `docs_scripts/` точечно выключены только правила неоднозначной кириллицы RUF001–RUF003: русский — документированный язык прозы валидаторов.

Три контрактных документа владеют машинными фактами, и код к ним привязан проверками: перечень полей конфигурации с умолчаниями (`cli-config.md`), таблица классов завершения (`cli-json.md`) и закрытая сводка устройства (`device-passport.md`). Каждая проверка испытана на срабатывание — два списка, которые совпадают и никем не проверяются, это два списка, которые разойдутся, а документ читают раньше, чем появится код.

Хуки разведены по стоимости. `pre-commit` выполняет `docs-check` и `back-static`, но не запускает тысячи backend-тестов, сборку wheels или install-regression. Полные `back-check` и `just check` выполняются на push и в CI. Причина практическая: хук, отнимающий больше минуты, обходят через `--no-verify`, а обойдённый хук не защищает ничего.

Правило `LN002` в `docs_lint` требует, чтобы имя документа в обратных кавычках вело к существующему файлу. Проверка ссылок Markdown этого не видит, потому что это не ссылка, — и так подряд пережили две висячие ссылки: cli-api-contract в `ADR-0013` и contracts/component-setup-manifests.md в `ADR-0012` (имена приведены без обратных кавычек намеренно: за ними не стоит файла, и правило право их отвергать). Оба документа были свёрнуты, упоминания остались и читались как действующие.

Отдельный гейт достижимости проверяет, что ни одна публичная функция уровня модуля в `apps/cli`, `apps/api`, `apps/platform` и `apps/worker` не существует без вызывающего в первопартийном исходнике. Тесты не считаются вызывающими: иначе функция, которую зовёт только её тест, выглядела бы живой. Обработчики FastAPI и конструкторы pydantic не считаются сиротами только потому, что до них доходят декоратор или создание модели. `packages/*` в множество определений не входят: это публичный API с потребителями вне репозитория. Гейт появился после того, как четыре предохранителя оказались написаны, задокументированы, покрыты тестами — и не подключены ни к чему. Покрытие такое не видит: функция, до которой доходит только её собственный тест, покрыта на 100% и мертва.

`back-static` держит нативные проекции Skill порождёнными, а не написанными руками: проекция с собственной копией перечня команд разошлась бы с реестром на первом же изменении. Обратная операция — `back-gen`, которая перегенерирует и `schemas/v1`, и проекции Skill.

Со спринта 1 проверка схем внутри `back-static` покрывает два артефакта, а не один: пофайловые схемы и документ `schemas/v1/openapi.json`. Оба порождаются одним генератором из одних моделей, поэтому расхождение между ними невозможно по построению, а гейт ловит ручную правку. Контрактные проверки дополнительно валидируют сам документ валидатором OpenAPI — проверки каждой схемы компонента метасхемой недостаточно, потому что документ вокруг них является собственной спецификацией, — и проверяют, что каждый встроенный пример соответствует своей схеме, что каждый опубликованный тип достижим из маршрута и что корпус фикстур выдерживает свои инварианты по `docs/contracts/fixture-corpus.md`.

- возраст evidence ограничен;

## Именование рецептов

`justfile` держится на дуальности: `gen` пишет, `check` читает. Всё остальное — те же две операции, суженные до одной группы. Группа является владельцем проверки, и префикс обязателен:

| Префикс | Владелец | Агрегат |
|---|---|---|
| `docs-*` | документационное основание: specs, ADR, `docs/`, MkDocs | `docs-check` |
| `back-*` | Python: `packages/`, `apps/api`, `apps/platform`, `apps/cli`, `tests/` | `back-check` |
| `web-*` | `apps/web` | `web-check` |

У каждой группы один и тот же набор глаголов, поэтому команду выводят, а не запоминают:

| Глагол | `docs-` | `back-` | `web-` |
|---|---|---|---|
| `gen` — переписать машинный текст | оглавления и таблицы | `ruff format`, `schemas/v1`, проекции Skill | `prettier --write`, типизированный клиент из контракта |
| `static` — прочитать исходник, не запуская | доклинтеры, Markdown, YAML, расхождение оглавлений | `ruff format --check`, `ruff check`, `pyright`, паритет схем и проекций | ESLint, Prettier check, TypeScript 7 |
| `test` — прогнать тесты | unit-тесты валидаторов | `pytest` с порогом покрытия | Vitest с порогами покрытия |
| `build` — собрать артефакт | `mkdocs build --strict` | колёса всех пакетов в `dist/` | `next build` |
| `regress` — прогнать собранный артефакт в реальном движке | render диаграмм в Mermaid | установка колеса в чистый venv и через `uv tool` | Playwright поверх production-сборки |
| `check` — агрегат группы | `static`, `test`, `build`, `regress` | то же | то же |

Никакой `-check` ничего не пишет: расхождение порождённого с источником ловится в `-static` и чинится явным вызовом `-gen`. Отдельный рецепт остаётся вызываемым сам по себе, чтобы падение воспроизводилось точечно, без прогона соседних групп.

Вне групп остаются `setup`, `hooks`, `gen`, `check`, `pre-commit` и `security`. Алиасы не заводятся: `ci` и `pre-push` были вторыми именами `check` и удалены. Git pre-commit hook вызывает быстрый `just pre-commit`; полный `just check` остаётся push/CI-гейтом.

`security` общий для репозитория, а не групповой: сканер зависимостей пока один (`bun audit`). Python-сканер добавляется в тот же рецепт, когда будет выбран, а не пустым `back-security` заранее.

## Frontend (`apps/web`)

Фронтовые проверки входят в `just check` через `web-check`. Локальный и CI-путь совпадают (issue #82/#83, ADR-0043). На раннере нужен `bun` (workflow ставит его через `oven-sh/setup-bun`); отсутствие `bun` валит рецепт, а не пропускает шаг. Установка зависимостей по `bun.lock` живёт в общем `just setup`, а не отдельным рецептом.

Порядок в `web-check` фиксирован: статика, тесты, сборка, регрессия в браузере. Default-профиль сайта для `web-build` и CI — `public_saas`; `self_hosted` проверяется отдельным явным profile-run. `web-regress` зависит от `web-build`, потому что Playwright поднимает `next start` поверх production-сборки и проверяет desktop и мобильный viewport. Рецепт устанавливает только закреплённые browser bytes в пользовательский cache. Системные библиотеки входят в образ self-hosted runner и не устанавливаются из проверки: `just check` не вызывает `sudo` и не ждёт пароль администратора.

`web-test` меряет покрытие всегда: сначала обычный `test:coverage`, затем
`test:coverage:catalog` из `vitest.catalog.config.ts` с порогом 95%
`statements` / `branches` / `functions` / `lines` на фиксированном наборе
файлов каталога. Отдельного рецепта для покрытия нет намеренно: порог, который
не вызывается из `just web-test`, был бы справочной цифрой.

Пороги покрытия читаются с оговоркой. Строчный порог измеряет то, что заявляет; пороги веток и функций у провайдера `v8` завышены неимпортированными файлами — файл, который не загрузил ни один тест, отдаёт 0% строк и 100% веток, потому что ветвлений в нём не насчитано вовсе. Поэтому расти обязан именно строчный порог, а ветки и функции держатся как защита от регресса и повышаются только вместе со строчным.

## Enforcement

GitHub Actions исполняет те же команды, что и локальные рецепты, но вызывает их
напрямую: `just` остаётся удобством машины разработчика и не является
зависимостью опубликованного гейта (проверяется тестом). Объединение job покрывает
ровно листья `just check` — это тоже проверяется механически, не на глаз.

По одному менеджеру пакетов на язык. Python — `uv` по корневому `uv.lock`;
инструменты документации живут группой `docs`, инструменты разработки — группой
`dev`. Node — `bun` по `docs_scripts/bun.lock` для инструментов документации и
`apps/web/bun.lock` для веба. `pip`, `npm`, `npx` и `pnpm` в гейте не
вызываются; сами `uv` и `bun` ставятся из подписанных релизных архивов
скриптами `.github/scripts/install-uv.sh` и `install-bun.sh` со сверкой
контрольной суммы.

Проверки идут на стандартных GitHub-hosted раннерах публичного дерева, где
минуты бесплатны и не ограничены (`ADR-0110`). Отдельного предпродакшн-яруса нет
по `ADR-0084`: среда одна, поэтому проверка перед развёртыванием — это
`just check`, а не второй контур.

Развёртывания в `check.yml` нет вовсе, и это не то же самое, что «нет в CI».
Оно живёт отдельным workflow `deploy.yml`, срабатывает от зелёного `check` на
`main` и только продвигает один монотонный ref; сам перенос выполняет целевой
хост своим таймером (`ADR-0103`). Источник этого ref — публичный репозиторий,
поэтому забор идёт анонимным HTTPS и на хосте не остаётся ключа развёртывания
(`ADR-0109`). Разделение доменов доверия из `ADR-0046` сохраняется сильнее

Jobs `check` и `back-python-3.12` запускаются на push в `main` и на
каждый pull request. Ветки push в workflow обязаны совпадать с линией из
`git-workflow.md`. Устаревший run вытесняется на любом событии: прерывать больше
нечего, а пока класс проверок принимает один job за раз, устаревший run — это не
потраченный слот, а остановленная очередь. Какой job на каком классе флота и
почему — `docs/operations/ci-cd.md` и `ADR-0100`; здесь это не дублируется.

Обязательными эти статусы не делаются, и это решение, а не ограничение платформы
(`ADR-0115`). Репозиторий не несёт защит на участников: ни branch protection, ни
обязательных одобрений, ни защищённых окружений, ни правил тегов. Причина в том,
кто здесь работает: основной участник — coding agent, и каждое такое правило
ставит в его цикл шаг, который он выполнить не может, при этом ни одно из них не
проверяет само изменение. Изменение проверяет гейт.

Граница проходит по одной линии, и её стоит держать в голове при следующем
подобном вопросе: правило, которое проверяет **изменение**, остаётся; правило,
которое проверяет **разрешение**, уходит. Поэтому гейт, allowlist публикуемых
путей и подтверждение необратимой операции в продукте — не «защиты» в этом
смысле и никуда не делись.

Существование workflow без наблюдаемого запуска и правил ветки не считается обеспечением требования. После каждого слияния в `main` проверяется точный merge SHA; успешный запуск PR на другом дереве не заменяет проверку основной линии.

`just evidence-live` доказывает анонимный срез против развёрнутой среды: точная
идентичность развёрнутого коммита, машинная поверхность, анонимный каталог,
равенство проекции CLI и опубликованного каталога и офлайн-повтор, отдающий
точный объект из кэша без утверждения свежести. Рецепт не входит в `just check`
и не может в него входить: гейт репозитория не вправе зависеть от внешней среды,
иначе её недоступность читается как красный код. Сценарии, требующие человека
или детерминированного тестового окружения провайдера, попадают в отчёт как
`not_verified` с причиной, а не опускаются.
