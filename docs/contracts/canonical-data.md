# Канонические данные

## Владелец контракта

После появления исполнимого кода владельцами полей являются версионируемые схемы в `schemas/`, OpenAPI и публичная схема протокола провайдеров. Документы объясняют смысл, но не создают альтернативные имена полей. До появления схем этот документ вместе с `SPEC-015` является нормативным источником.

## Идентификаторы

Устойчивая сущность получает непрозрачный `stable_id` с префиксом типа. Идентификатор не зависит от пути, отображаемого имени, версии или устройства и никогда не переиспользуется.

Ревизия получает `revision_id`, вычисленный из канонических данных ревизии: `revision_` и 64 шестнадцатеричных символа хэша в домене `ai-stp:revision:v1` по `ADR-0036`. Случайного пути создания идентификатора ревизии не существует. Опубликованный артефакт, паспорт версии, план и пакет получают отдельные адресуемые по содержимому идентификаторы.

Отдельной сущности «манифест версии» не существует по `ADR-0012`: описанием неизменяемой версии является её паспорт. Слово «манифест» сохраняется только за ограниченной таблицей файлов внутри пакета по `harness-bundle.md` и за манифестом выпуска провайдера по `provider-release.md`; ни то, ни другое не является идентичностью версии.

## Каноническая сериализация

Структурированные данные сериализуются как UTF-8 JSON по RFC 8785 после нормализации Unicode в NFC. Повторяющиеся ключи, нечисловые значения, неоднозначные десятичные числа, метка порядка байтов и неизвестная несовместимая версия схемы отклоняются до хэширования.

Время записывается в UTC по RFC 3339 с миллисекундами и суффиксом `Z`. Версия `X.Y` хранится строкой, но сравнивается как два неотрицательных целых числа.

Путь внутри артефакта использует `/`, является относительным, не содержит пустые сегменты, `.` или `..` и сравнивается после Unicode- и регистрозависимой проверки целевой файловой системы.

## Области хэшей

Для разных объектов используются разные области:

```text
ai-stp:artifact:v1
ai-stp:passport:v1
ai-stp:revision:v1
ai-stp:plan:v1
ai-stp:bundle:v1
ai-stp:attestation:v1
ai-stp:native-discovery:v1
ai-stp:project-index:v1
ai-stp:project-toolchain:v1
ai-stp:project-configuration:v1
ai-stp:selection-snapshot:v1
```

Три области `project-*` принадлежат паспорту проекта и разделены между собой:
опись файлов, установленный набор инструментов и конфигурация проекта — разные
факты, и совпадение их содержимого не должно давать один идентификатор.

Область `selection-snapshot` принадлежит снимку входа сеанса рекомендации по
`selection-proposal.md`: ревизии паспортов контекста, выбранный харнесс, точные
кандидаты и версия политики. Именно её изменение делает предложение устаревшим,
поэтому она отделена от паспортов, из которых собрана.

Область `native-discovery` принадлежит воспроизводимому кандидату read-only
обнаружения по `ADR-0054` и `ADR-0055`. Она связывает объявленный layout, область,
harness, отредактированный путь и allowlisted source provenance, но не создаёт
устойчивую логическую идентичность Component: такую идентичность выдаёт только
явное принятие.

Хэш вычисляется как SHA-256 от имени области, нулевого байта и канонических байтов. Одинаковое содержимое в разных областях не должно давать взаимозаменяемый идентификатор.

Поле `ArtifactRef.digest` всегда использует область `ai-stp:artifact:v1` и точные
байты артефакта. Голый SHA-256 ZIP-контейнера HarnessBundle принадлежит отдельному
полю `bundle_artifact_digest` по `harness-bundle.md`; он не является `ArtifactRef`
и не проверяется как доменный хэш артефакта. Локальный кэш хранит эти пространства
раздельно, поскольку строка `sha256:...` сама не кодирует область хэша.

## Точная ссылка

Ссылка на версию компонента содержит устойчивый идентификатор, необязательную нативную реализацию, версию и хэш паспорта:

```json
{
  "stable_id": "component_...",
  "variant_id": "variant_...",
  "version": "1.2",
  "passport_digest": "sha256:..."
}
```

Ссылка на версию сетапа не содержит вариант: сетап принадлежит одному харнессу по `ADR-0014`, поэтому нативная реализация не является отдельной осью его идентичности.

```json
{
  "stable_id": "setup_...",
  "version": "1.2",
  "passport_digest": "sha256:..."
}
```

Поле `variant_id` допустимо только в ссылке на компонент и только когда у компонента действительно есть отдельные нативные реализации. Оно обозначает реализацию, а не отдельную линию версий.

Плавающие ветки, теги, диапазоны версий и значение `latest` не являются сохраняемой ссылкой.

## Подпись

Подпись покрывает канонический хэш паспорта или артефакта с областью, идентификатор политики доверия и допустимый контекст выпуска. Ключ или издатель из недоверенного манифеста не становится доверенным автоматически. Конверт подписи не включает сам себя в подписываемые данные.

## Изменения

Изменение канонизации, области хэша или несовместимого набора полей требует новой версии схемы, эталонных векторов, окна двойного чтения и явной миграции. Старые опубликованные хэши не пересчитываются.
