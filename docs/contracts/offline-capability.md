# Граница автономной работы

Владелец решения — `ADR-0019`, владелец требований — `SPEC-001` и `SPEC-014`. Здесь зафиксирована машинная граница: какие операции обязаны работать без сети после успешной первичной настройки и какие возвращают типизированную причину.

Автономность считается только после успешной первичной настройки. До неё продукт честно сообщает, что набор инструментов и провайдеры ещё не получены.

## Автономные операции

| Область | Поведение без сети |
|---|---|
| Паспорта разработчика и проекта | чтение, изменение, ревизии |
| Индекс проекта | полное сканирование и повторное сканирование |
| Локальный реестр | чтение, черновики, регистрация, фиксация версий |
| Импортированные и собственные объекты | выбор, проверка, установка |
| Поиск | локальный индекс и ранее полученный кэш каталога |
| Подбор и сборка | из локальных и кэшированных кандидатов |
| Проверки | установленными инструментами набора |
| Пакет и план | построение и осмотр |
| Установка и запуск | применение, состояние, восстановление, запуск из кэшированных артефактов |

## Операции, требующие сети

| Область | Причина |
|---|---|
| Первая некэшированная загрузка инструмента или выпуска провайдера | артефакт ещё не получен |
| Вход и связывание identity | внешний провайдер |
| Некэшированный облачный поиск | серверный индекс |
| Доступ к закрытым облачным объектам | проверка права на сервере |
| Синхронизация | обмен ревизиями |
| Публикация | серверная проверка и неизменяемый снимок |
| Приглашения и права | серверное состояние и почта |
| Отправка жалобы | серверный случай модерации |
| Обновление сведений об отзыве и блокировке | свежесть политики |
| Живая проверка удалённых MCP | внешняя точка подключения |

## Правила поведения

Автономная операция использует только ранее проверенные кэшированные артефакты и не смягчает требования целостности, версий и политики доверия.

`registry acquire --id <setup_id> --version <X.Y>` получает полное exact
замыкание опубликованного setup и атомарно делает его доступным локальному
сборщику. Вариант `--offline` не открывает сеть: он повторно проверяет сохранённые
паспорта и artifact bytes, а при отсутствии любого узла отказывает без частично
материализованного графа. Acquisition не выбирает setup и не изменяет target.

При повторном чтении кэш заново проверяет размер и исходную область digest:
`ArtifactRef` — в `ai-stp:artifact:v1`, а exact HarnessBundle — по отдельному raw
SHA-256 ZIP. Эти байты лежат в разных пространствах кэша и не подменяют друг друга.

Выход из аккаунта имеет две половины, и без сети выполняется только одна. Серверный отзыв сессии требует подключения, локальное забывание учётных данных — нет, и оно выполняется в любом случае: отказ оставил бы токен на диске, что хуже, чем сессия, пережившая его. Невыполненный серверный отзыв возвращается предупреждением в конверте и не меняет код завершения. Владелец требования — `SPEC-002` `REQ-219`.

Кэшированное состояние каталога показывается вместе со временем последней проверки. Устаревшее сведение о блокировке не выдаётся за актуальное.

Недоступность сети даёт `degraded` или типизированную причину, но не превращается в пустой успешный результат и не отключает локальные функции.

Отзыв устройства прекращает будущие облачные операции и не удаляет локальные данные и уже проверенные кэшированные байты.
