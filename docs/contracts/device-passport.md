# Паспорт устройства

Владелец требований — `SPEC-002`; решение о разделении контекста принадлежит `ADR-0025`. Здесь зафиксирована машинная граница: какие поля принадлежат паспорту устройства, что из них покидает устройство и в каком виде.

Паспорт устройства — изменяемый ревизионируемый паспорт вида `device` по `passport-envelope.md`. Он описывает окружение одной установки CLI и принадлежит этому устройству. Факты внутри него подчиняются общим осям происхождения и подтверждения по `ADR-0021`.

## Разделение владения

| Факт | Владелец |
|---|---|
| Роль, типовые задачи, предпочтения, автономность | `DeveloperPassport` |
| Предпочитаемые языки и харнессы, история решений | `DeveloperPassport` |
| Операционная система и архитектура | `DevicePassport` |
| Установленные харнессы и их точные версии | `DevicePassport` |
| Версии инструментов набора и адаптеров | `DevicePassport` |
| Возможности и наблюдаемые факты окружения | `DevicePassport` |
| Стек, версии, команды и требования проекта | `ProjectPassport` |
| Выбранный харнесс и активный сетап проекта | `ProjectPassport` |

Поле, попадающее под две строки таблицы, является ошибкой модели: у каждого факта ровно один владелец. Наблюдаемый факт установки никогда не записывается в паспорт разработчика, даже как «предпочтение по умолчанию»: предпочтение заявляется пользователем, а не выводится из окружения молча.

## Поля

Паспорт устройства содержит:

- `device_id` — идентификатор устройства из `SPEC-002`;
- отображаемое имя устройства, заданное пользователем;
- операционную систему и архитектуру;
- обнаруженные харнессы с точными версиями и состояниями по `SPEC-014`;
- версии установленных инструментов профиля `mvp-full` и адаптеров;
- возможности окружения: доступные среды исполнения и их версии;
- наблюдаемые факты окружения с происхождением и подтверждением.

Пути источников наблюдений хранятся в локальном состоянии детектора. В синхронизируемые ревизии паспорта устройства абсолютные пути пользовательских каталогов не входят.

## Приватность и синхронизация

Паспорт устройства приватен и принадлежит устройству. При включённой синхронизации сервер хранит по каждому устройству отдельную разрешённую сводку; полные паспорта устройств между собой не объединяются, и межустройственного «общего окружения» не существует.

Разрешённая сводка устройства закрыта по составу:

- отображаемое имя устройства;
- операционная система и архитектура;
- перечень обнаруженных харнессов с версиями;
- версия профиля набора инструментов;
- время последнего обновления сводки.

Секретные значения, значения переменных окружения и абсолютные пути в сводку не входят. Страницы устройств в вебе показывают только эту сводку; публичный профиль остаётся отдельным объектом по `ADR-0023` и данных устройства не получает.

## Использование в подборе

Вход подбора собирается из паспорта разработчика, паспорта текущего устройства, паспорта текущего проекта и выбранного харнесса. Требования к самому подбору принадлежат `SPEC-006`; этот контракт лишь фиксирует, что факты окружения берутся из паспорта устройства, а не из паспорта разработчика.

## Идентичность устройства и паспорт устройства

Это разные объекты, и путать их не следует. Идентичность — это `device_id`, пара ключей Ed25519 и состояние отзыва: она создаётся при первом запуске CLI, офлайн, до появления аккаунта, и её машинная форма опубликована как `cli-device-identity`. Паспорт устройства описывает окружение и появляется вместе с локальным реестром.

Приватный ключ хранится по `ADR-0058`: в системном хранилище секретов, когда на машине действительно есть доверенный backend, и в файле с правами владельца в остальных случаях. Использованный ярус входит в ответ и в проверку `doctor`; молчаливого отката нет. Публичная половина лежит в обычном файле, потому что её нужно показывать; приватной половине не соответствует ни одно поле ни одной модели репозитория, поэтому напечатать её нечем.

## Отзыв устройства

Отзыв устройства прекращает приём его событий синхронизации по `SPEC-002` и не удаляет локальный паспорт устройства: локальное чтение сохраняется, а сводка на сервере помечается отозванной вместе с устройством.

Локальный сброс идентичности не переиспользует ни идентификатор, ни ключ по `SPEC-002` REQ-207 и запоминает отставленный идентификатор — не переиспользовать отозванное устройство можно только помня его. Локальные данные сброс не трогает.
