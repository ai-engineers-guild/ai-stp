# SPEC-011: CLI, машинная справка и навык агента

## Цель

Пользователь устанавливает CLI командой с сайта через `uv`, а агент безопасно управляет паспортами, индексом, композицией, проверками и установкой через стабильный машинный контракт и канонический навык.

## Границы

Входят установка и первичная настройка, строгий JSON, справка возможностей и схем, разделение плана и применения, ежедневный цикл работы, один глобальный пользовательский конфиг, семь проекций навыка, защищённый управляющий слой и граница повышения привилегий. Графический оркестратор, скрытые команды оболочки, собственный вызов модели и передача пароля агенту не входят.

## Термины

- `machine help` — версионируемое описание команд, полей, класса изменения и следующих действий.
- `control-plane Skill` — защищённая интеграция `ai_stp`, отдельная от заменяемого пользовательского сетапа.
- `full-auto` — профиль работы агента с кодом, а не безусловное разрешение внешних действий; одна из трёх независимых осей по `ADR-0017`.
- `global config` — единственный пользовательский файл настроек CLI, не содержащий секретов.

## Требования

- `REQ-1101`: CLI устанавливается опубликованной командой через `uv` в пользовательское окружение без обязательного `sudo`.
- `REQ-1102`: Машинный вывод использует один строгий версионируемый объект JSON в стандартном выводе и устойчивые классы завершения и ошибок; машинная справка публикует для каждого error code отдельный `handling`, потому что общий exit class не определяет действие агента.
- `REQ-1103`: Чувствительное изменение имеет неизменяемый план и отдельное применение с точным хэшем.
- `REQ-1104`: Автоматическая работа с кодом не отменяет подтверждение публикации, основной версии, установки неподтверждённого объекта, повышения привилегий, полной очистки, удаления цели или резервной копии и внешнего действия Git или развёртывания.
- `REQ-1105`: Один канонический навык агента создаёт проверяемые нативные проекции для семи харнессов.
- `REQ-1106`: Навык получает команды, схемы и обработку ошибок из машинной справки, а не копирует параметры, коды завершения или error disposition вручную.
- `REQ-1107`: Управляющий навык не удаляется и не перезаписывается пользовательским сетапом.
- `REQ-1108`: Пароль, токен и секрет повышения привилегий никогда не передаются агенту, аргументам CLI, стандартному вводу, окружению или журналу.
- `REQ-1109`: Неизвестный харнесс и найденные у него нативные конфигурации фиксируются как неизвестные наблюдения; сетап, вариант, цель и черновик адаптации для них не создаются, а попытка применения возвращает ошибку `AI_STP_UNSUPPORTED_APPLY` со списком поддерживаемых харнессов.
- `REQ-1110`: Действия чтения, черновика, добавления, удаления, обновления и установки компонента объявлены в машинной справке и всегда проходят через версию сетапа, пакет и план провайдера.
- `REQ-1111`: Обнаруженная нативная конфигурация без зарегистрированного сетапа сначала оформляется в личный сетап отдельным явным шагом.
- `REQ-1112`: Ежедневная работа выражена действиями `status`, `rescan`, `search`, `diff`, `update` и `rollback`; автоматическое обновление, каналы выпуска и фоновый демон отсутствуют.
- `REQ-1113`: `status` показывает проект, сетап, харнесс, выбранную и установленную версии, состояние ожидающей установки, оба вида расхождения и результат проверки обязательных переменных окружения по именам.
- `REQ-1119`: Расхождение различает `local_drift` — цель изменена вне жизненного цикла провайдера и не соответствует паспорту установленной версии — и `catalog_drift` — для закреплённого объекта доступна более новая версия; ожидание установки выбранной версии расхождением не является и показывается состоянием `pending_install`, а каждое состояние называет своё безопасное следующее действие.
- `REQ-1120`: Ни один вид расхождения не устраняется автоматически: `local_drift` предлагает восстановление или оформление изменений в новую версию, `catalog_drift` предлагает обновление после плана.
- `REQ-1114`: Один глобальный пользовательский конфиг задаёт доступность и адрес публичного каталога, включение облачной синхронизации, путь локального реестра, параметры локального поиска, явные корни обнаружения проектов, а также включение и адрес анонимного пинга телеметрии; закрытый перечень полей и значения по умолчанию принадлежат `docs/contracts/cli-config.md`.
- `REQ-1115`: Конфиг не содержит секреты, не заменяет паспорта, а неизвестный ключ возвращает понятную типизированную ошибку.
- `REQ-1116`: CLI показывает действующую конфигурацию без секретов, а приоритет определяется как значение по умолчанию, затем глобальный конфиг, затем явный аргумент команды.
- `REQ-1117`: Автономный режим достигается отключением каталога и синхронизации в конфиге и не требует других изменений.
- `REQ-1118`: CLI и каждая его команда не вызывают интерфейсы моделей, не требуют model credential и не зависят от optional server presentation enrichment `SPEC-053`.
- `REQ-1121`: Сеанс рекомендации, показ предложений и подтверждение объявлены в машинной справке; создание `SetupVersion` из предложения доступно только через действие подтверждения по `docs/contracts/selection-proposal.md`.
- `REQ-1122`: Команда жалобы объявлена в машинной справке, собирает только механические поля разрешённого перечня `docs/contracts/report-case.md`, показывает полный предпросмотр и отправляет случай только после явного согласия пользователя.
- `REQ-1124`: Диагностика сообщает предусловия составления сетапа отдельной проверкой, состояние которой остаётся `ready` при их отсутствии, а `detail` называет точные команды создания недостающих паспортов. Список этих команд имеет одного владельца и совпадает с тем, что называет отказ соответствующей команды.
- `REQ-1123`: Для интеграционных сценариев машинная справка позволяет построить argv без разбора prose: обязательность, тип, повторяемость и закрытые значения параметров структурированы, а каждый payload связан с опубликованной схемой; обновление выражено точным выбором версии и `install plan` с `action=update`, а не скрытой автоматической командой.

## Состояния и ошибки

Первичная настройка имеет состояния `ready`, `needs_user_action`, `partial` и `failed`. `ready` означает, что установка исправна, а не что доступно всё, что умеет сборка: предусловия отдельных команд состоянием не управляют и сообщаются в `detail` соответствующей проверки. Машинный JSON всегда различает повторяемые и постоянные ошибки. Авария до построения конверта может использовать поток ошибок, но не печатает секреты. Неподдерживаемая команда или схема возвращает типизированное указание обновления.

## Безопасность и приватность

CLI использует системное защищённое хранилище для облачных учётных данных и пользовательские каталоги для набора инструментов. Содержимое репозитория и вывод инструмента считаются недоверенными. Агент не подтверждает собственную внешнюю запись. Повышение привилегий выполняется только через системное взаимодействие с человеком или возвращает `needs_user_action`.

## Совместимость и миграция

Машинный JSON, справка и проекция навыка имеют версии. Неизвестные необязательные поля игнорируются; неизвестная основная версия схемы отклоняется. Версия генератора проекций и хэш канонического навыка записываются, а смысловая потеря блокирует доверенную проекцию.

## Критерии приёмки

| Требование | Исполнимый способ проверки |
|---|---|
| `REQ-1101` | Чистая установка на Linux x86_64 выполняет опубликованную команду без прав администратора; неподтверждённая macOS line не называется поддержанной. |
| `REQ-1102` | Эталонные проверки JSON, кодов завершения и полного error registry проверяют стандартные потоки, разные handling для conflict/user-decision одного класса и неизвестные поля. |
| `REQ-1103` | Изменённый или устаревший план блокирует применение. |
| `REQ-1104` | Проверки политики взаимодействия требуют решения пользователя для каждого чувствительного класса. |
| `REQ-1105` | Эталонные проекции покрывают Claude Code, Codex, Pi, OpenCode, Grok Build, Cursor и Antigravity. |
| `REQ-1106` | Контрактная проверка навыка получает параметры и error handling только из `help --agent --json` и не содержит ручной таблицы exit classes. |
| `REQ-1107` | Сквозная проверка переключения сетапа сохраняет управляющий навык. |
| `REQ-1108` | Проверки процессов и журналов подтверждают отсутствие паролей и секретов. |
| `REQ-1109` | Фикстура неизвестного харнесса не создаёт ни одного управляемого объекта и возвращает типизированную ошибку со списком поддерживаемых. |
| `REQ-1110` | Контрактная проверка доказывает, что добавление компонента создаёт новую версию сетапа и не пишет в цель напрямую. |
| `REQ-1111` | Сквозная проверка на цели без сетапа требует явного шага оформления до применения. |
| `REQ-1112` | Машинная справка объявляет ровно эти шесть действий, а поиск по коду не находит планировщика автоматических обновлений. |
| `REQ-1113` | Эталонный ответ `status` содержит все перечисленные поля и не содержит значений переменных. |
| `REQ-1114` | Фикстура конфига покрывает каждое поле и значение по умолчанию. |
| `REQ-1115` | Неизвестный ключ и секретоподобное значение отклоняются с указанием места ошибки. |
| `REQ-1116` | Проверка приоритета доказывает порядок и отсутствие секретов в выводе действующей конфигурации. |
| `REQ-1117` | Отключение каталога и синхронизации проходит автономный сквозной путь. |
| `REQ-1118` | Проверка dependency closure и запуска CLI отклоняет клиент модели, model credential и зависимость от enrichment endpoint. |
| `REQ-1119` | Фикстура изменённой мимо провайдера цели даёт `local_drift`; другой stable ID с тем же `X.Y` даёт `pending_install`; `catalog_drift` появляется только для численно большей canonical версии (`1.10 > 1.9`), не появляется для более старого каталога и не смешивается с local drift. |
| `REQ-1120` | Ни одна фикстура расхождения не изменяет цель без отдельного решения пользователя. |
| `REQ-1121` | Контрактная проверка не находит пути создания версии из предложения мимо действия подтверждения. |
| `REQ-1122` | Фикстура жалобы показывает предпросмотр, отклоняет отправку без согласия и не содержит полей вне разрешённого перечня. |
| `REQ-1124` | Тест доказывает, что установка без паспортов даёт `ready` с `detail`, называющим обе команды, и что владелец списка команд один. |
| `REQ-1123` | Контрактный тест для search, discover, adopt, status, diff и rollback строит обязательные параметры и enum только из machine help, проверяет существование каждого `result_schema`; update plan принимает только объявленное значение `action=update`. |
