# SPEC-017: Каркас серверного приложения и наблюдаемость

## Цель

Серверные точки входа `apps/api` и `apps/worker` получают детерминированный каркас: сборку приложения фабрикой, управляемый жизненный цикл зависимостей, единый машинный конверт ответа, безопасный маппинг ошибок, независимые проверки жизни и готовности и наблюдаемость. Каркас не содержит бизнес-правил веба или CLI и не дублирует локальную логику. Владелец платформенных требований в целом остаётся `SPEC-010`; здесь описан только слой исполнения.

## Границы

Входят фабрика приложения, `lifespan`, типизированные настройки, привязка ответа к конверту `ai_stp_foundation.envelope`, корреляция запроса и трасса, маппинг исключений на реестр кодов, эндпоинты `liveness` и `readiness`, генерация и проверка OpenAPI против фикстур `#71`, провайдер OpenTelemetry и структурный лог. Не входят: схема базы и объектное хранилище (`SPEC-010`, `#79`), вход, аккаунты и устройства (`SPEC-002`, `#80`), доменные области реестра и каталога (`#81`), очередь заданий (`SPEC-018`) и упаковка развёртывания (`SPEC-019`).

## Термины

- `App factory` — чистая функция, которая по валидированным настройкам собирает экземпляр приложения без модульного глобального состояния.
- `Envelope` — единый машинный конверт ответа `SuccessEnvelope`/`ErrorEnvelope` из `ai_stp_foundation.envelope`.
- `Readiness` — состояние готовности принимать нагрузку, ложное до применения миграций и доступности обязательных зависимостей.
- `Observability provider` — сквозной слой OpenTelemetry и структурного лога, общий для `api` и `worker`.

## Требования

- `REQ-1701`: `api` и `worker` собираются детерминированной фабрикой по валидированным настройкам без модульного глобального состояния приложения.
- `REQ-1702`: Обязательные зависимости поднимаются в `lifespan` и освобождаются при остановке; недоступность обязательной зависимости даёт типизированный отказ старта, а не отложенную ошибку на первом запросе.
- `REQ-1703`: Настройки берутся только из явных env-источников через типизированную модель без секрет-дефолтов; отсутствие обязательного секрета даёт типизированный отказ старта.
- `REQ-1704`: Ошибка `/v1` использует конверт `ErrorEnvelope` / `CliError` из `ai_stp_foundation.envelope` (тот же wire, что CLI). Успех несёт **тело ресурса** из моделей `#71` (не CLI `SuccessEnvelope`); `operation_id` при изменении — в заголовке `X-Operation-Id` и/или в теле, если модель ресурса его объявляет. Правило владельца: `docs/contracts/http-api.md` и `packages/contracts`.
- `REQ-1705`: Каждый ответ несёт корреляцию `X-Request-Id` (тело ресурса его не дублирует); входящий заголовок принимается и продолжается, исходящее значение возвращается; `trace_id` связывается со спаном OpenTelemetry.
- `REQ-1706`: Необработанное исключение отображается на `AI_STP_INTERNAL` с exit-классом из реестра без stacktrace и секретов в ответе; категории `validation`, `auth`, `conflict`, `rate`, `dependency` и `internal` отображаются на зарегистрированные коды, а коды и статусы берутся из общей таблицы без магических чисел в обработчиках.
- `REQ-1707`: `liveness` независим от зависимостей и не обращается к базе или хранилищу.
- `REQ-1708`: `readiness` ложен, пока миграции не применены и обязательные зависимости `PostgreSQL` и `RustFS` недоступны; ответ перечисляет неготовые зависимости из закрытого набора.
- `REQ-1709`: OpenAPI генерируется из кода, а проверка эквивалентности доказывает семантическое совпадение с фикстурами `#71`; расхождение проваливает проверку.
- `REQ-1710`: Провайдер наблюдаемости инициализируется как сквозной слой, экспортёр задаётся конфигурацией, а недоступный бэкенд не роняет приложение.
- `REQ-1711`: Структурный лог пишется в дневной файл с ротацией в полночь и в stdout; поля ограничены закрытым набором; токены и персональные данные не логируются, а владельцем правила остаётся `SPEC-013`.

## Состояния и ошибки

Приложение имеет состояния запуска `starting`, `ready` и `stopping`. До `ready` оно отвечает на `liveness`, но `readiness` остаётся ложным. Отказ обязательной зависимости при старте является типизированной ошибкой запуска и не переводит приложение в `ready`. Ошибка ответа различает категории `validation`, `auth`, `conflict`, `rate`, `dependency` и `internal`; каждая категория отображается на зарегистрированный код `AI_STP_*` с его exit-классом. Необработанное исключение всегда становится `AI_STP_INTERNAL` без утечки внутренних подробностей.

## Безопасность и приватность

Секреты поступают только из env-источников и не имеют значений по умолчанию. Ответ об ошибке не содержит stacktrace, значений секретов или внутренних путей. Структурный лог использует закрытый набор полей и не пишет токены и персональные данные. Провайдер наблюдаемости не экспортирует содержимое секретов и полезной нагрузки запроса.

## Совместимость и миграция

Тела ресурсов и ошибок следуют направленной совместимости `docs/engineering/schema-evolution.md`: производитель строит строгие модели и не эмитит неизвестные поля, а потребитель терпит необязательные добавления. OpenAPI считается проекцией кода, а истина контракта живёт в фикстурах `#71`; ломающее изменение получает новую версию по `docs/contracts/http-api.md`. Формат структурного лога расширяется только добавлением необязательных полей.

## Критерии приёмки

| Требование | Исполнимый способ проверки |
|---|---|
| `REQ-1701` | Тест фабрики собирает два независимых экземпляра приложения без общего глобального состояния. |
| `REQ-1702` | Тест старта с недоступной обязательной зависимостью получает типизированный отказ, а не ошибку на первом запросе. |
| `REQ-1703` | Отрицательный тест при отсутствии обязательного секрета получает типизированный отказ старта без секрет-дефолта. |
| `REQ-1704` | Контрактный тест ASGI: успех — тело ресурса `#71` без CLI success-envelope; ошибка — `ErrorEnvelope` с `AI_STP_*`. |
| `REQ-1705` | Тест корреляции проверяет заголовок `X-Request-Id`, продолжение входящего значения и связь `trace_id` со спаном. |
| `REQ-1706` | Тест необработанного исключения получает `AI_STP_INTERNAL` без stacktrace и секрета, а матрица категорий отображается на реестр кодов без литералов. |
| `REQ-1707` | Тест `liveness` отвечает успехом при недоступной базе. |
| `REQ-1708` | Матрица `readiness` покрывает отсутствие миграций, базы и хранилища и перечисляет неготовые зависимости. |
| `REQ-1709` | Проверка эквивалентности OpenAPI и фикстур `#71` падает при искусственном расхождении. |
| `REQ-1710` | Тест наблюдаемости стартует приложение при недоступном экспортёре без отказа. |
| `REQ-1711` | Тест лога подтверждает дневной файл, закрытый набор полей и отсутствие токенов и персональных данных. |
