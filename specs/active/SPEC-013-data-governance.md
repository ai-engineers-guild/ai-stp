# SPEC-013: Управление пользовательскими данными

## Цель

Платформа минимизирует сбор данных, сохраняет закрытую модель по умолчанию, делает административный доступ наблюдаемым и обеспечивает предсказуемые права, экспорт, удаление и хранение до работы с реальными пользователями.

## Границы

Входят паспорт разработчика, публичная проекция, закрытые объекты, сводка индекса проекта, аудит администратора, метки удаления, физическая очистка и срок хранения резервных копий. Сквозное клиентское шифрование и скрытое от администраторов содержимое не входят в MVP.

## Термины

- `PublicProfile` — отдельный объект, который пользователь заполняет самостоятельно.
- `AccessGrant` — отдельное право, а не знание идентификатора аккаунта или адреса почты.
- `GrantInvitation` — предложение доступа до подтверждения адреса входом.
- `Tombstone` — логическое удаление до физической очистки.
- `RetentionPolicy` — утверждённые сроки хранения основных данных, аудита и резервных копий.

## Требования

- `REQ-1301`: Паспорт разработчика закрыт; публичный профиль является отдельным объектом и наполняется только явным действием пользователя.
- `REQ-1302`: Идентификатор аккаунта и адрес почты не предоставляют доступ без отдельного действующего `AccessGrant`.
- `REQ-1303`: Каждое чтение закрытого объекта проверяет владельца, право или административное полномочие.
- `REQ-1304`: Административное чтение и изменение подтверждения, публичности, блокировки или права журналируются с причиной и результатом.
- `REQ-1305`: В MVP отсутствует сквозное клиентское шифрование; этот факт явно раскрывается пользователю.
- `REQ-1306`: Полный индекс проекта и исходный код не загружаются без отдельного решения пользователя.
- `REQ-1307`: Секреты, исходные диалоги, полная история оболочки и значения окружения не собираются.
- `REQ-1308`: Удаление немедленно отзывает обычный доступ и создаёт метку удаления до физической очистки.
- `REQ-1309`: Физическая очистка идемпотентна, учитывает хранилище объектов и резервные копии и оставляет минимальную запись аудита.
- `REQ-1310`: Политики хранения, экспорта и удаления резервных копий утверждаются до публичного запуска серверного режима.
- `REQ-1311`: Прямой адрес, ключ хранилища или идентификатор артефакта не заменяет проверку полномочий.
- `REQ-1312`: Журналы, трассы и метрики не содержат исходный текст закрытого объекта, значение секрета или необязательные персональные данные.
- `REQ-1313`: Синхронизируемые ревизии паспорта устройства и его разрешённая сводка не содержат абсолютные пользовательские пути, значения переменных окружения и секреты; пути источников остаются в локальном состоянии детектора.
- `REQ-1314`: Полезная нагрузка жалобы ограничена разрешённым перечнем `docs/contracts/report-case.md`; личность репортёра видна только модераторам, автор получает очищенное уведомление, а журналы модерации не содержат закрытых байтов и секретов.
- `REQ-1315`: Anti-abuse публичных usage counters не хранит raw IP, user-agent,
  идентификатор account/device или стабильный идентификатор посетителя; dedup evidence живёт
  короткий документированный срок, а публична только сумма.
- `REQ-1316`: Клиентская телеметрия выключена по умолчанию; до явного согласия
  исходящих запросов телеметрии нет ни одного, а отказ и «ещё не спрашивали»
  наблюдаемо неразличимы. Согласие даётся отдельной командой с подтверждением;
  запись `telemetry.enabled=true` в обход неё отклоняется.
- `REQ-1317`: Пинг телеметрии — один неаутентифицированный HTTPS `GET` с закрытым
  перечнем полей `docs/contracts/cli-telemetry.md`, без тела, cookie, токена
  каталога и авторизации. Локальные пути, приватные репозитории, аккаунт, ключ
  устройства, почта, имя проекта, путь цели, значения окружения и содержимое
  файлов в него не попадают; при отсутствии публично называемого объекта запрос
  не отправляется.
- `REQ-1318`: Пинг уходит только после `verified` применения с действием
  `install` или `update`, по одному на фактически установленный компонент.
  Сетевая ошибка, timeout и ответ вне 2xx проглатываются молча: результат
  установки не зависит от доступности коллектора и повтор пачкой не выполняется.
- `REQ-1319`: Анонимный идентификатор создаётся только при согласии, хранится в
  локальном каталоге данных вне конфигурации, не совпадает с `device_id` и не
  связан с аккаунтом; отказ и выключение его удаляют, повторное согласие даёт
  новый, и он не объединяется с публичными usage counters (`REQ-1315`).

## Состояния и ошибки

Закрытый объект имеет состояния `active`, `shared`, `access_revoked`, `tombstoned`, `purge_pending` и `purged`. Право имеет состояния `active`, `expired` и `revoked`. Приглашение имеет состояния `pending`, `accepted`, `expired` и `revoked` и до подтверждения не даёт доступа. Ошибка очистки остаётся в состоянии ожидания и повторяется идемпотентно. Ошибка экспорта не меняет исходные данные.

## Безопасность и приватность

PostgreSQL и RustFS доступны только серверным компонентам. Действия администратора используют минимальные полномочия и неизменяемый аудит. Журналы строятся по разрешённому списку полей и очищаются. Резервные копии не становятся обходом отзыва доступа и удаляются по утверждённой политике.

## Совместимость и миграция

Изменение класса данных или срока хранения требует версии политики и плана миграции. Старые записи аудита сохраняют исходный смысл. Физическое удаление начинается только после подтверждения, что поддерживаемым версиям объект не нужен для отката или объединения конфликта.

## Критерии приёмки

| Требование | Исполнимый способ проверки |
|---|---|
| `REQ-1301` | Изменение паспорта не меняет публичный профиль, а незаполненный профиль не отдаётся как публичная страница. |
| `REQ-1302` | Проверка полномочий отклоняет доступ по идентификатору аккаунта и по адресу почты без права. |
| `REQ-1303` | Матрица покрывает владельца, получателя права, постороннего и администратора. |
| `REQ-1304` | Проверка аудита фиксирует каждое служебное чтение и изменение. |
| `REQ-1305` | Пользовательская политика и метаданные API явно сообщают видимость оператору. |
| `REQ-1306` | Проверки синхронизации не отправляют полный индекс и исходный код без согласия. |
| `REQ-1307` | Фикстуры очистки подтверждают отсутствие запрещённых классов данных. |
| `REQ-1308` | Запрос удаления немедленно блокирует обычное чтение и создаёт метку. |
| `REQ-1309` | Повтор очистки безопасен и удаляет копии базы и хранилища по политике. |
| `REQ-1310` | Производственная конфигурация отклоняется без версионируемой политики хранения. |
| `REQ-1311` | Прямой адрес или ключ хранилища возвращает отказ. |
| `REQ-1312` | Проверки журналов, трасс и метрик проверяют разрешённые поля и очистку. |
| `REQ-1313` | Фикстура паспорта устройства с путями и значениями окружения синхронизирует ревизию без них. |
| `REQ-1314` | Матрица полномочий скрывает личность репортёра от автора, а фикстуры журналов модерации не содержат закрытых байтов. |
| `REQ-1315` | Privacy tests подтверждают keyed digest без raw IP, user-agent, account/device и короткий срок dedup evidence; публична только сумма. |
| `REQ-1316` | Без согласия фикстура установки не порождает исходящего запроса; `config set telemetry.enabled=true` без согласия отклоняется типизированной ошибкой; отказ и `not_asked` дают одинаковую сетевую наблюдаемость. |
| `REQ-1317` | Собранный запрос содержит ровно перечисленные поля и ни одного вне списка; фикстуры с локальным путём, приватным репозиторием и переменной окружения не дают запроса или не выносят этих значений. |
| `REQ-1318` | Отказ коллектора и timeout оставляют операцию `verified`; `backup`, `rollback`, `remove` и чтения запроса не порождают; сетап из трёх компонентов даёт три запроса. |
| `REQ-1319` | Отказ и выключение удаляют идентификатор; повторное согласие даёт другой; он не равен `device_id` и не появляется в обычном выводе состояния. |
